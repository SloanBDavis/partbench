- Recorded: **2026-08-02**

## Landed Product Path

- The browser owns a lazy, private `partbench-exact-artifact-v1` OPFS cache.
  Keys bind the canonical body source identity signature, source cache hash,
  kernel protocol, OCCT build, artifact/writer/format versions, and shape
  policy. Hits are also rejected unless artifact document identity and units
  match the current expected identity. Warm reads keep the original bytes but
  still parse the B-rep and recompute metadata/topology before reuse.
- Entries are capped at 128 MiB, the cache at 512 MiB and 4,096 records, with
  deterministic `lastAccess`/key LRU eviction. Corrupt, stale, and
  version-mismatched entries are removed; unavailable, denied, or full OPFS
  falls back to a cold rebuild. Clear invalidates in-flight writes before
  removing only derived exact data.
- Project UI reports source-only JSON portability, makes `.wcad` primary when
  checkpoints are required, lists every missing checkpoint, and labels the JSON
  fallback explicitly.
- Recovery accepts one user-selected `.wcad`, validates every requested
  project/checkpoint/body/feature/length/hash/topology identity, and replaces
  app-owned payloads only when the complete request matches. It never changes
  document source/history or consults the derived cache.

## Outstanding Gate Evidence

This record does not close Gate E. The required production-browser proof for
native OPFS cache behavior, recovery/download file interaction, accessibility,
and no eager OPFS/OCCT startup has not run. The current sandbox rejects the
necessary loopback listener with `EPERM`; the Vitest portability workflow uses
an in-memory OPFS target and is not a substitute for that browser evidence.

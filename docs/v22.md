# V22 Release Plan: Precision Interaction and Recovery

Status: **Approved for implementation (2026-08-03).**

V22 is a focused usability release on top of the completed V18–V21.1
foundation. It makes the existing exact single-part modeling matrix directly
selectable, previewable, measurable, and recoverable without adding another
modeling family or widening a completed support row.

The product label **V22** is unrelated to the existing minimum-triggered
project schema `web-cad.project.v22`. This plan adds no authoritative source
shape, so the project schema remains minimum-triggered through
`web-cad.project.v22` and `.wcad` remains `partbench.wcad.v2`.

There is no Stretch section. Every outcome in this document is Must unless it
is explicitly listed as a non-goal. An implementation DAG must freeze fixtures,
protocol details, and landing order before production changes begin.

Approval records the user's explicit V22 implementation directive on
2026-08-03. It does not waive a completed modeling Must, compatibility row,
or non-goal.

V21.1 gzip ceilings and inherited command-worker / OCCT WASM overages are not
V22 Must items. Bundle sizes may be measured as informational evidence. They
are not a fail-the-release tripwire for Gate E, H, I, or the release. Gate E
passed on `pnpm smoke:v22-preview-grips-workflow` plus focused real-OCCT
preview/Apply same-shape parity. See
[Removed requirements (2026-08-30)](#removed-requirements-2026-08-30).

## Product Goal

After V22, the following statement must be true:

> A user can point at the exact body, face, edge, or vertex they see; understand
> whether it is merely selectable or valid for the active command; preview an
> existing supported feature edit before committing it; inspect exact values;
> and recover the latest successfully captured dirty revision after an
> interrupted browser session.

A user must be able to:

1. hover, select, highlight, filter, and cycle body, face, edge, and vertex
   candidates on every active exact-ready body within the documented resource
   limits;
2. use a current exact pick in every existing collector whose completed
   command matrix accepts that semantic target, without making every selected
   entity falsely commandable;
3. complete the same selection workflow by keyboard from a bounded candidate
   list;
4. see a cancellable exact transient preview for every completed solid-feature
   create/update row before Apply;
5. edit the bounded numeric fields in the V22 grip matrix from either a
   viewport grip or the existing right editor, with both paths compiling to the
   same existing CADOps update operation;
6. see and edit existing sketch dimensions on canvas without persisting label
   layout or adding a dimension/constraint family;
7. inspect exact single-target and bounded two-target measurements with an
   explicit authority label and no fabricated approximate fallback;
8. activate one display-only section plane without creating datum or section
   geometry;
9. receive a visible dirty-project warning before destructive project
   replacement or browser unload; and
10. restore or discard the latest valid browser-owned `.wcad` recovery snapshot
    after a crash, reload, or interrupted session.

## Why V22 Comes After V21.1

V18 established one precision workbench shell, one action registry, keyboard
and focus contracts, responsive docks, and a shared editor draft model. V19
completed the approved production sketching matrix. V21 and V21.1 made every
completed active body resolve through one current exact artifact and closed
the downstream-body and exact-export gaps.

The remaining usability bottleneck is interaction, not another source family:

- current body/object picking is bounds-based;
- generated planar-face and generated-edge picking cover only a documented
  source-semantic subset and use display-space reconstruction;
- arbitrary current exact faces, edges, and vertices cannot all be selected or
  highlighted from the rendered result;
- supported solid feature forms do not provide one general exact transient
  preview path;
- sketch dimensions are source-authoritative but their annotations remain
  editor/session state;
- measurement support is split between source-analytic simple cases and
  injected exact metadata rather than one exact subentity workflow;
- section view is absent; and
- dirty project state is visible but is not backed by one crash-recovery
  snapshot and a consistent project-replacement guard.

V22 uses the exact artifact, topology snapshot, renderer visual-state,
selection-intent, editor, `.wcad`, and OPFS boundaries already present. It does
not create a second geometry resolver, renderer, command system, storage
format, or workflow owner.

## Scope Ledger

| Gap after V21.1 | V22 disposition |
| --- | --- |
| Body/object viewport hits are bounds-based | Replace solid-mode body hits with triangle-depth hits when a current exact display mesh is ready; retain a truthful body-only fallback when it is not |
| Generated face/edge picking covers a source-semantic subset | Add same-shape exact topology pick maps for every exact-ready body |
| Generated vertices are not pickable | Include current exact vertex positions and semantic binding |
| Selection and commandability can be conflated | Keep universal selection separate from the completed operation eligibility matrix |
| Overlapping candidates are hard to disambiguate | Add deterministic filtering, cycling, and a keyboard candidate list |
| Solid feature forms lack one exact preview path | Add one app-owned transient preview orchestrator over existing CADOps and the V21 resolver |
| Numeric feature edits live primarily in the editor | Add the bounded grip matrix; keep the right editor as the complete accessible path |
| Existing sketch dimensions are not continuously visible/editable on canvas | Add session-laid-out annotations for the completed dimension matrix |
| Exact subentity and pair measurements are incomplete | Add the bounded exact measurement matrix |
| Section/clipping is absent | Add one display-derived section plane with explicit non-authoritative copy |
| Dirty projects have no crash recovery | Add one browser-owned atomic `.wcad` recovery project with at most two retained generations |
| Recent-project library, cloud autosave, or direct source-file autosave | Defer; one local recovery project is sufficient for V22 |
| New feature, constraint, dimension, datum, direct-edit, assembly, drawing, or interchange breadth | Non-goal |

## Non-Negotiable Architecture

1. `CadDocument`, transaction history, existing checkpoint source records, and
   committed CADOps remain authoritative.
2. Renderer hit IDs, triangle ranges, edge polylines, vertex display points,
   depth values, pick filters, preview meshes, grips, annotations, section
   planes, and measurement pins remain derived or UI session state.
3. Exact pick identity is bound to the current body source identity and exact
   topology signature. A stale pick never resolves against a replacement
   artifact.
4. Universal selection does not imply universal commandability. Cad-core keeps
   ownership of lifecycle, dependency legality, operation eligibility,
   durable-reference legality, and semantic diffs.
5. The renderer reports private display hits. It does not construct generated
   references, topology anchors, CADOps, or command-readiness decisions.
6. Geometry construction, exact topology extraction, subshape measurement, and
   same-shape pick-map creation remain behind geometry-kernel,
   geometry-worker, and occt-wasm.
7. React does not infer a topology entity from mesh coordinates or reconstruct
   a feature recipe from the selected triangle.
8. Durable downstream references continue to use existing generated-reference
   or topology checkpoint/anchor commands. Hover and selection alone never
   create project source.
9. Exact preview uses the same CADOps operation and current exact-body resolver
   as commit. Preview is never authorization to skip commit-time validation.
10. Preview artifacts never enter history, redo, `.wcad`, JSON, checkpoint
    payloads, or the V21.1 exact artifact cache.
11. Recovery snapshots are browser-owned full `.wcad` packages, not derived
    geometry cache entries. They become project source only after explicit
    Restore and ordinary package validation.
12. Empty projects and ordinary sketch startup do not instantiate OCCT, build
    pick maps, generate preview geometry, or open OPFS merely because V22 is
    installed.
13. Human and connected-agent commits retain the same existing command layer.
    V22 adds no natural-language parser, agent viewport authority, raw file
    access, approval mode, or hosted transport.
14. V22 adds no production dependency, workspace package, project schema,
    `.wcad` version, generic preview framework, generic job framework, or new
    renderer.

## Binding Decisions

### 1. Derive Pick Data From the Same Exact Shape

The V21/V21.1 exact-body artifact already binds B-rep, metadata, topology, and
display mesh to one current source identity. V22 extends the transient exact
display result with a pick map produced during the same OCCT shape lifetime as
the topology snapshot and tessellation.

The internal transferable contract is equivalent to:

```ts
interface ExactViewportPickMap {
  readonly version: "partbench.exact-pick-map.v1";
  readonly bodyId: BodyId;
  readonly bodySourceIdentitySignature: string;
  readonly topologySignature: string;
  readonly meshVertexCount: number;
  readonly meshTriangleCount: number;
  readonly faces: readonly ExactFaceTriangleRange[];
  readonly edges: readonly ExactEdgeDisplayPolyline[];
  readonly vertices: readonly ExactVertexDisplayPoint[];
}

interface ExactFaceTriangleRange {
  readonly localId: string;
  readonly entitySignature: string;
  readonly firstTriangle: number;
  readonly triangleCount: number;
}

interface ExactEdgeDisplayPolyline {
  readonly localId: string;
  readonly entitySignature: string;
  readonly points: Float64Array;
}

interface ExactVertexDisplayPoint {
  readonly localId: string;
  readonly entitySignature: string;
  readonly point: readonly [number, number, number];
}
```

Exact field names may follow package conventions, but these semantics are
binding:

- every referenced local ID and signature exists in the accompanying exact
  topology snapshot with the same kind;
- face ranges are non-overlapping, in bounds, and together describe every
  selectable tessellated face triangle;
- edge polylines and vertex points come from the same exact subshapes, not from
  React reconstruction or public stable IDs;
- all numbers are finite and all counts, offsets, and byte lengths are bounded;
- pick data is transferred, not JSON/base64 encoded;
- a mismatched mesh count, body identity, topology signature, entity signature,
  or range invalidates the complete pick map; and
- failure to create a valid pick map leaves body selection available and exact
  subentity selection explicitly unavailable. It never guesses.

Pick maps are private derived data. They are not saved to source, `.wcad`, JSON,
history, redo, checkpoints, or OPFS caches.

### 2. Use the Current Canvas Renderer; Do Not Add a Selection Renderer

V22 keeps the existing renderer abstraction and Canvas 2D implementation.
Exact solid picking uses:

1. current body bounds for cheap rejection;
2. ray/triangle depth against the displayed exact mesh for body and face hits;
3. projected, depth-aware tolerance against exact edge polylines and vertex
   points; and
4. the pick map to bind the private display hit to one current exact topology
   entity.

Clipped or occluded candidates are not preferred over a nearer visible
triangle. Edge and vertex tolerance is expressed in CSS pixels and remains
stable across device pixel ratio. The active collector's required entity kind
may affect candidate priority, but it cannot make an occluded candidate visible
or change source legality.

The initial implementation uses body-bound rejection and a bounded direct
triangle scan. A private per-mesh acceleration index may be added only if the
named V22 hover performance fixture misses its gate. That index remains an
internal renderer detail; V22 does not approve a scene graph, generic BVH
package, GPU color-pick buffer, WebGL rewrite, or WebGPU renderer.

### 3. Keep Display Hits Private and Semantic Evidence Explicit

The renderer returns a private hit record. The app validates it against the
current exact result before constructing bounded current-topology evidence:

```ts
interface CadCurrentTopologySelectionEvidence {
  readonly bodyId: BodyId;
  readonly bodySourceIdentitySignature: string;
  readonly topologySignature: string;
  readonly entityKind: "face" | "edge" | "vertex";
  readonly localId: string;
  readonly entitySignature: string;
}
```

This evidence is query/interaction input only. It is not a new `CadOp`, saved
reference, feature target, or project record. Raw renderer IDs, triangle
indices, selection-buffer IDs, OCCT handles, and pick-map offsets never enter
visible text, agent results, audit metadata, semantic diffs, or project source.

The screen-space hit remains a tessellated display approximation. Existing hit
precision must not be relabeled `exact` merely because its semantic binding is
current exact topology. V22's exact claim is the verified identity of the
selected topology entity and any subsequent OCCT measurement, not an exact
analytic intersection between the pointer ray and the B-rep.

V22 extends the existing `selection.referenceCandidates` query with one
mutually exclusive `currentTopologyEvidence` input. The existing
`CadSelectionReferenceInput`, `CadTopologyCommandTargetInput`,
`CadViewportHitCandidate`, and every authoritative command member remain
unchanged. Existing private viewport inputs may retain `rendererHitId` and
`selectionBufferHitId`; those values cannot enter the new evidence member or
leave the private viewport boundary.

The current-topology response must distinguish:

- current and selectable;
- current and inspect-only;
- an existing generated reference match;
- an existing topology-anchor match;
- promotable through the existing checkpoint/anchor workflow for an operation
  already supported by the completed matrix;
- blocked by lifecycle, topology health, operation policy, or missing
  checkpoint evidence; and
- stale, ambiguous, missing, resource-limited, or unsupported.

Cad-core validates document-owned facts. The browser/geometry boundary validates
current exact evidence. Neither boundary may claim the other's proof.

`promotable` is not a generic local-ID-to-anchor conversion. It applies only
when the current exact entity verifies against an existing generated reference
that the completed body/face/edge checkpoint-and-anchor workflow already
accepts. Arbitrary exact local IDs and current exact vertices remain
inspect-only when no such existing durable match exists.

### 4. Universal Selection Is Not Universal Commandability

Every current exact-ready face, edge, and vertex within limits is selectable,
highlightable, and inspectable. Command collectors remain limited to their
completed operation matrices.

For example:

- selecting an arbitrary exact edge does not make chamfer or fillet available
  if the completed edge-finish matrix rejects that body/reference row;
- selecting a non-planar face does not make sketch-on-face available;
- selecting any face on a valid V21.1 shell target may feed the existing
  open-face collector only when the current topology reference passes shell
  readiness;
- a current topology entity may remain inspect-only when no durable promotion
  path exists; and
- no viewport affordance may bypass target consumption, dependency-cycle,
  source-identity, exact preflight, or reference-health checks.

When an existing command requires a durable reference, Apply uses the existing
generated-reference or topology checkpoint/anchor promotion path in the same
transactional workflow as the feature command. Hover, click, multiselect, and
measurement never promote source automatically.

### 5. Selection Filters and Disambiguation Are Session State

Solid and Inspect modes expose exactly these filters:

```text
Auto | Body | Face | Edge | Vertex
```

`Auto` prioritizes the entity kind requested by the active collector, then the
nearest visible face, edge, vertex, and body using one deterministic ordering.
An explicit filter never changes command legality.

At one pointer location:

- repeated activation of the existing cycle shortcut advances through the
  bounded ordered candidate list;
- moving outside the pointer tolerance resets the cycle;
- Shift retains the existing additive-selection meaning;
- Escape clears the current collector/preselection according to the V18 stack;
- the status surface announces kind, human label, index, count, and
  commandability; and
- the right-side candidate list exposes the same ordering and operations for
  keyboard-only use.

At most 64 candidates are retained for one pointer location. Additional
candidates produce a structured truncation diagnostic and are reachable by
changing the filter or view. Filters, cycle position, hover, and preselection
are not persisted in the project.

### 6. One Transient Exact Preview Path Serves Existing Features

V22 adds one app-owned preview orchestrator. It does not add a preview command
or a second feature recipe resolver.

For each preview request the app:

1. builds the same existing CADOps batch that Apply would submit;
2. runs existing dry-run/source validation;
3. applies that batch to one disposable engine/project projection rather than
   the live engine;
4. computes the projected source identity;
5. resolves only the affected result through the V21/V21.1 exact-body resolver;
6. tessellates the transient result through the existing worker boundary;
7. verifies live revision, source identity, preview sequence, and editor
   ownership before display; and
8. releases every transient artifact, buffer, and OCCT handle on every terminal
   path.

Every ID that the operation may create is materialized before the first preview
and reused by Apply. Preview, dry-run, and commit do not allocate competing IDs.
The disposable projection may read current validated checkpoint payloads and
unchanged dependency artifacts through existing browser-owned boundaries, but
it never writes a checkpoint or cache entry. Its projected source identity is
an internal preview binding, not a promise that a later live transaction will
have identical project-package bytes.

The preview mesh is visibly ghosted and non-selectable. For target-replacing
operations, the current target is subdued while the projected result is shown;
V22 does not compute a second exact red/green volumetric difference merely for
presentation.

At most one exact preview job is active. A new draft, selection change, mode
change, Apply, Cancel, Escape, undo, redo, New, Open, recovery Restore, worker
restart, or live source change cancels or stales the previous job. Preview
artifacts never write the exact artifact cache.

The UI acknowledges input by the next animation frame with the changed grip or
draft state and a pending indicator. Exact preview completion is asynchronous.
Failure leaves current committed geometry visible and reports a localized human
diagnostic with Technical Details.

Apply reconstructs the operation from the live editor draft, reruns all source
and exact preflight checks, and commits through the normal command executor.
Matching preview output never skips revalidation.

V21.1's browser preflight rule remains binding: geometry-dependent widened
commits carry current transient preflight proof for the captured cad-core
source-authority epoch. A preview or direct cad-core dry-run is not that proof,
and stale, cancelled, failed, or differently bound preview preflight can never
be reused by Apply.

### 7. Freeze the Preview and Grip Matrix

The complete V22 preview and direct-grip matrix is:

| Existing feature family | Create preview | Update preview | V22 direct grip fields |
| --- | --- | --- | --- |
| Extrude, including completed entity/wire/region and add/cut rows | Must | Must | Depth |
| Revolve, including completed entity/wire/region rows | Must | Must | Angle |
| Circular blind/through-all hole on the V21.1 target matrix | Must | Must | Blind depth only |
| Chamfer | Must | Must | Distance |
| Fillet | Must | Must | Radius |
| Linear pattern | Must | Must | Spacing; count through the grip value editor |
| Circular pattern | Must | Must | Total angle; count through the grip value editor |
| Mirror | Must | Must | Plane offset |
| Shell | Must | Must | Wall thickness |
| Sweep in the completed V17 matrix | Must | Must | None; editor preview only |
| Loft in the completed V16/V17 matrix | Must | Must | None; editor preview only |
| Imported body, primitive compatibility object, delete, suppress, reorder, or unsupported row | No new preview promise | No new preview promise | None |

“Must” applies only where the current command row is already supported. V22
does not turn a deferred create/update row into a supported one.

Grip behavior is binding:

- dragging changes only the listed scalar field;
- an adjacent value editor provides typed numeric entry with current units;
- Enter previews/applies according to the existing editor contract and Escape
  restores the committed value without source mutation;
- keyboard arrows provide bounded increments and Shift uses the existing larger
  increment convention;
- the right editor mirrors every value and remains the complete accessible path;
- a parameter/expression-bound field is read-only at the grip and routes to the
  owning parameter/expression editor rather than silently replacing the
  binding with a literal; and
- invalid, zero, non-finite, out-of-range, or geometry-infeasible values remain
  blocked before commit with the existing diagnostic vocabulary where possible.

No face push/pull, arbitrary edge move, direct B-rep edit, inferred feature
creation, or new parameter binding is approved by this matrix.

### 8. Put Existing Sketch Dimensions on Canvas

Sketch mode renders annotations for the complete existing V19 dimension matrix.
The annotation shows the evaluated value, units where applicable, and the
existing radius/diameter or angle sense. Selecting an annotation opens the
existing dimension editor; double activation or Enter focuses its value input.

Dragging an annotation changes only UI label position for the current session.
Editing its value submits the existing normalized
`sketch.dimension.update` command. Parameter-bound dimensions route to the
parameter editor and do not discard the binding.

Annotations avoid overlap using one deterministic bounded placement pass over
visible dimensions. The user may reposition a label for the session. Layout,
leader geometry, hidden state, and viewport zoom are not project source and are
not saved. V22 adds no dimension, constraint, solver residual, or annotation
schema.

### 9. Add One Bounded Exact Measurement Contract

Inspect mode accepts one or two current exact selections. A measurement request
is bound to body source identities, topology signatures, entity local IDs, and
entity signatures and runs through the geometry worker when OCCT evaluation is
required.

The V22 single-target matrix is:

| Selection | Exact values |
| --- | --- |
| Body | Existing exact volume, surface area, centroid, bounds, and inertia |
| Face | Area, surface class, and normal/axis/radius where mathematically defined |
| Edge | Length, curve class, midpoint, and radius where mathematically defined |
| Vertex | Model-space coordinates |

The exact two-target matrix is deliberately narrower. `D` means exact minimum
distance with closest points only when one deterministic pair exists. `A`
means the exact supporting-plane or supporting-line angle. Body measurements
remain single-target; body/body and body/subentity pairs are unavailable in
V22.

| First × second | Body | Face | Edge | Vertex |
| --- | --- | --- | --- | --- |
| Body | Unavailable | Unavailable | Unavailable | Unavailable |
| Face | Unavailable | D; A only when both planar | D | D |
| Edge | Unavailable | D | D; A only when both linear | D |
| Vertex | Unavailable | D | D | D |

Every other pair angle is structured unavailable and returns no approximate
number. Pair targets may belong to the same body or two different bodies and
must be distinct current topology entities.

Measurements use at most two targets. Exact topology evidence must still be
current after worker completion. Missing payloads, partial topology, stale
identity, unsupported geometry, worker failure, and resource limits produce
structured diagnostics without changing selection or source.

The UI always labels authority. Existing source-analytic simple-body values may
remain visible, but a V22 subentity/pair result is labeled exact only when it
comes from current exact artifact/topology evidence. Tessellated coordinates
are never reported as exact measurement values.

Users may pin at most 32 measurement readouts for the current browser session.
Pins retain semantic/current-topology evidence and become visibly stale rather
than silently rebinding after source change. Pins, label placement, and
measurement history are not saved or restored.

Plane/line angle is the smallest unsigned angle between the supporting planes
or lines in the closed range 0–90 degrees. Parallel and coincident support is
reported as 0 degrees with the applicable classification. Minimum distance is
always authoritative; closest points are included only when the exact solver
returns one current deterministic pair, otherwise the response reports the
distance with a non-unique-closest-point diagnostic.

### 10. Section View Is Display-Only

V22 supports one active section plane in Inspect mode:

- XY, XZ, or YZ;
- a currently selected planar exact face; or
- the same plane with a finite user-controlled offset and flipped normal.

The renderer clips displayed triangles and exact pick candidates consistently.
The cut is labeled **Display section**. It creates no datum, sketch, face,
section curve, hatch, topology entity, feature, measurement authority, export
geometry, or project state. Measurements continue to use the uncut exact body
unless the user explicitly selects visible current topology.

Activating a selected-face section copies its current exact plane frame into
session state; the plane does not silently follow or rebind after later source
changes. Newly exposed cut interiors and optional visual caps are never
selectable faces because no authoritative topology entity exists for them.

The section plane, offset, flip, and enabled state are session-only. Clearing
the selection does not silently change the plane. New, Open, recovery Restore,
and explicit Reset view clear it.

### 11. Recovery Stores One Browser-Owned Project Safely

V22 adds one recoverable project, not a recent-project database.

After a committed source change makes the project dirty, the app lazily exports
the current project through the existing `.wcad` v2 writer, including every
currently available authoritative checkpoint payload. Coalesced writes retain
at most two generations for that one project:

1. write a new generation under a new private OPFS name;
2. close it;
3. read and validate package version, source identity, byte length, SHA-256,
   manifest, and checkpoint payloads through the ordinary `.wcad` reader;
4. publish a small current-generation record only after validation; and
5. remove generations older than the previous validated fallback.

A failed, cancelled, quota-limited, corrupt, stale, or interrupted write leaves
the prior valid generation available. Preview drafts, pointer drags, UI state,
and uncommitted editor changes never schedule a recovery write.

Temporary or unpublished generation files are removed on the next recovery
access after validation and may never accumulate without bound. The product
surface shows whether recovery is pending, current, unavailable, or failed and
provides one **Clear recovery data** action in the existing Project/Storage
owner.

A small bounded local-storage marker may indicate that recovery metadata
exists. Startup reads that marker first and opens OPFS only when needed. The
marker is untrusted and cannot restore a project; Restore always reads and
validates `.wcad` bytes. No OCCT or exact cache load is triggered merely to
check recovery status.

On startup with a valid recovery generation, the app shows one accessible
Restore/Discard choice with project name, last committed time, source identity
summary, units, body count, and portability state. It never replaces the
current document automatically.

Restore uses the existing atomic `.wcad` open path, hydrates matching
checkpoint payloads, clears stale previews/selections/jobs, and opens as an
unsaved dirty project. It does not pretend that a browser file handle or prior
download still exists. Discard removes both generations and the marker only
after explicit confirmation.

A successful explicit `.wcad` Save or Save As clears recovery only after the
saved package source identity matches the live project. New, Open, JSON load,
or recovery Restore does not discard a dirty live project until the user
chooses Save, Discard, or Cancel in the project-replacement guard.

The existing active-editor draft guard resolves before the project dirty guard.
Choosing Save permits replacement only after Save succeeds; a failed or
cancelled Save leaves the current project open. The app never starts or depends
on an asynchronous recovery write from `beforeunload`.

OPFS unavailable, denied, full, or corrupt is non-fatal but visibly reports
that crash recovery is unavailable. The browser `beforeunload` guard remains
active for every dirty project; browsers may display their own generic copy.

Recovery data is private browser storage. It is not an exact artifact cache,
checkpoint substitute, durable recent-file handle, cloud backup, automatic
write to the user's source file, or agent-accessible file surface. The status
surface reports the last successfully captured source revision so users are not
promised that a crash during the coalescing/write window preserves the newest
commit.

### 12. Preserve Accessibility, Responsiveness, and Interaction Ownership

Every pointer workflow has a keyboard-complete equivalent:

- exact hit candidates are available in the ordered candidate list;
- filters are labeled controls with a persistent selected state;
- cycling announces candidate index/count and commandability;
- grips are focusable and mirror the right editor;
- sketch dimension annotations are focusable without creating a keyboard trap;
- measurements expose values and authority as text, not color alone;
- section controls are operable without pointer dragging;
- preview pending/success/failure and recovery write/restore status use the
  existing live-region discipline; and
- project replacement and recovery choices restore focus to the invoking
  action or safe workbench landmark.

Hover is never the sole path to information or action. Selected, hovered,
command-target, warning, pending, and failed states remain visually distinct in
default and reduced-motion modes. Narrow layouts keep the viewport usable and
move candidate, measurement, preview, and recovery details into the existing
dock/drawer rules rather than adding a new shell.

### 13. Keep Versions and Dependencies Stable

V22 adds no authoritative source field. Therefore:

- V1–V22 JSON remains readable;
- minimum-schema export rules remain unchanged;
- `.wcad` remains `partbench.wcad.v2`;
- recovery stores an ordinary current `.wcad` package rather than a recovery
  format;
- selection, preview, grips, annotations, pins, and section state remain
  derived/session-owned;
- exact pick maps are transferable internal payloads, not persisted data;
- approval modes remain exactly `manualApproval` and `approveAll`; and
- no production dependency or workspace package is approved.

If implementation evidence shows that a Must outcome requires authoritative
annotation, measurement, view, or recovery source, this plan must be amended
and re-approved before a schema or package version changes.

## Public and Internal Contract Changes

### Cad Protocol

- add bounded current-topology selection evidence for query/interaction use;
- extend only `selection.referenceCandidates` with the mutually exclusive
  current-topology input and response projection frozen above;
- extend viewport diagnostics for stale exact evidence, invalid pick binding,
  resource-limited candidates, and inspect-only selection;
- add typed exact measurement request/response evidence without B-rep bytes,
  mesh coordinates, renderer IDs, OCCT handles, OPFS names, or file paths;
- retain every existing `CadOp`, command matrix, approval value, project schema,
  and `.wcad` version; and
- reject current-topology evidence from authoritative command/source fields.

### Cad Core

- validate current body lifecycle and existing durable-reference matches for
  current-topology selection queries;
- project operation commandability without treating derived evidence as source;
- provide or reuse one disposable project/engine projection path for preview
  source validation without modifying the live document, history, or redo;
- preserve existing dry-run, editability, semantic diff, undo/redo, and
  topology-anchor promotion behavior; and
- add no geometry, renderer, OPFS, or file-handle awareness.

### Geometry Kernel / Worker / OCCT WASM

- create and validate same-shape exact pick maps alongside current exact
  tessellation/topology;
- transfer face ranges, edge polylines, and vertex points with bounded typed
  arrays;
- resolve exact subshapes by validated current topology local ID/signature for
  the V22 measurement matrix;

## Resource, Failure, and Security Limits

V21/V21.1 exact artifact, graph, export, worker, and source-identity limits
remain binding. V22 additionally requires:

- at most one active exact preview job;
- at most one active exact measurement job per Inspect surface;
- at most 64 retained hit candidates at one pointer location;
- at most 512 simultaneously rendered sketch dimension annotations, with the
  remaining dimensions available in the existing editor/list and an explicit
  truncation summary;
- at most 32 pinned session measurements;
- at most one active section plane;
- at most one recovery project and two validated recovery generations;
- at most 250,000 triangle examinations in one synchronous direct hit-test;
  larger candidate work returns a structured resource-limited body-only
  fallback unless the measured private acceleration escape hatch is enabled;
- at most 128 MiB for one transferred pick map and 512 MiB aggregate retained
  pick-map bytes, with lower measured production limits permitted;
- recovery uses a third, source-owned private OPFS namespace distinct from both
  derived-cache roots, with at most 512 MiB per `.wcad` generation, 1 GiB for
  both generations, 128 MiB per ZIP entry, 12,300 ZIP entries, a 64 KiB
  generation record, and a 4 KiB local marker;
- safe-integer validation for every count, offset, range, and typed-array byte
  length before allocation or use;
- source identity checks before and after pick-map creation, preview projection,
  exact preview, exact measurement, recovery export, recovery validation, and
  recovery Restore;
- cancellation checks between body/subshape work and before every cache,
  recovery, or UI apply boundary;
- object URLs, temporary virtual files, transferred buffers, worker requests,
  and OCCT handles released in `finally` paths;
- no main-thread base64 conversion;
- no raw private IDs or storage names in visible copy, logs intended for users,
  agents, MCP, semantic diffs, or project files; and
- corrupt recovery packages pass the V22 byte/count ZIP preflight before the
  ordinary `.wcad` reader, and untrusted checkpoint B-rep reaches only the
  existing bounded OCCT/WASM path. Derived-cache clear never removes recovery,
  and recovery clear never removes either derived cache.

Resource failure degrades honestly:

- invalid/missing pick data retains body-only selection;
- preview failure retains committed geometry and editor draft;
- measurement failure retains selection but returns no fabricated number;
- section rendering failure disables the section and restores the full view;
  and
- recovery failure retains the live project and prior valid generation where
  present.

## Normative Release Scenarios

1. **Exact selection across the complete body matrix** — open one fixture per
   V21.1 exact-ready source family; hover/select/highlight a body, face, edge,
   and vertex; filter and cycle overlaps; repeat through the keyboard list; and
   prove current identity, occlusion, body fallback, and no mutation.
2. **Selection versus commandability** — select inspect-only and commandable
   entities on authored, imported, and recursive downstream results; prove the
   current feature matrices are unchanged; promote one supported topology
   target explicitly; Apply; undo; redo; save; and reopen.
3. **Exact create/update preview** — preview every row in the V22 matrix,
   replace rapid drafts, trigger one geometry failure, cancel, then Apply and
   prove the committed B-rep/topology/mass/display result matches the final
   preview source while preview itself changed no source.
4. **Parametric grips and sketch annotations** — edit each grip field by
   pointer, keyboard, and typed value; route a bound field to its parameter;
   edit representative existing sketch dimension kinds on canvas; and prove
   label positions do not persist.
5. **Exact inspection** — measure each single-target kind, minimum distance
   across two bodies, planar-face angle, and linear-edge angle; pin results;
   change source and show pins stale; activate a selected-face section plane;
   and prove clipping changes neither exact values nor export.
6. **Crash recovery** — commit imported/checkpoint-backed work, interrupt a new
   snapshot before publish, reload, restore the prior valid generation, save it,
   and prove source identity, checkpoint payloads, exact rebuild/cache behavior,
   history, dirty state, reported captured revision, and recovery cleanup.
7. **Failure and limit workflow** — exercise invalid/corrupt pick maps, more
   than 64 pointer candidates, oversized mapping, preview cancellation, stale
   measurement, OPFS denial/quota, corrupt recovery, worker restart, and memory
   cleanup without source loss or hidden fallback.

## Performance and Bundle Evidence

V21.1 gzip ceilings are not a V22 Must and do not fail Gate E, H, I, or the
release. `pnpm check:v22-bundle` may still record sizes as informational
evidence. The metric formula, minifier, and production dependencies stay
unchanged; changing them to hide a size is not an accepted close.

Historical V21.1 reference sizes, for measurement only:

```text

critical CSS                 20,480 bytes
all non-worker UI JavaScript 563,200 bytes
command worker               262,144 bytes
geometry worker              122,880 bytes
OCCT WASM                    13,808,536 bytes
```

The inherited final baseline measured 1,492 gzip bytes of critical UI, 8 of

  present and adds no duplicate cache/storage stack; and

  no extra unmetered command/query worker or parallel validator is permitted.

Runtime gates require:

- pointer/keyboard input feedback by the next animation frame;
- representative ready-mesh hover hit-testing p95 at or below 16 ms on the

  representative runs;
- one active preview and stale/cancelled results never apply;

## Rejected Alternatives

1. **Start V22 with assemblies or drawings.** Rejected because it multiplies
   interaction friction before the existing exact part workflow is directly
   usable.
2. **Treat a triangle index as a durable face reference.** Rejected because
   tessellation is derived and changes independently of authoritative topology.
3. **Make every selected exact entity commandable.** Rejected because selection
   breadth and completed modeling support are different contracts.
4. **Persist arbitrary current topology local IDs directly in features.**
   Rejected because durable use must retain checkpoint/anchor identity and
   repair semantics.
5. **Add a second feature preview protocol.** Rejected because the same existing
   CADOps batch can project a disposable source and use the current exact
   resolver.
6. **Write previews to the V21.1 exact cache.** Rejected because speculative
   drafts would pollute a validated current-source cache and complicate stale
   cleanup.
7. **Compute red/green volumetric differences for every preview.** Rejected
   because a subdued current result plus ghosted projected result communicates
   the decision without another exact boolean pipeline.
8. **Let grips replace parameter/expression bindings.** Rejected because a
   convenient drag must not silently change design intent.
9. **Report mesh-derived distances as exact.** Rejected because the exact
   artifact and topology boundary already exists.
10. **Store recovery in the derived exact cache.** Rejected because recovery is
    a validated source package and derived cache cannot replace source.
11. **Build a recent-project manager for one crash snapshot.** Rejected until
    measured use shows one recovery project is insufficient.
12. **Rewrite the renderer or add a dependency before measuring direct scan.**
    Rejected; body-bound rejection and direct scan are the first implementation,
    with only a measured private acceleration escape hatch.

## Risk Controls

| Risk | Control |
| --- | --- |
| Mesh hit is mistaken for topology authority | Same-shape pick map, current identity/signature validation, private hit record, explicit semantic evidence |
| “Universal selection” widens CAD behavior | Frozen source × kind × operation matrix and inspect-only state |
| Stale preview flashes or commits | One sequence-owned job, source/revision checks at every async boundary, commit revalidation |
| Preview duplicates feature recipes | Disposable projection uses the same CADOps and V21 resolver |
| Drag destroys parameter intent | Bound fields are read-only grips and route to their owner |
| Hover becomes slow on complex meshes | Bounds rejection, direct-scan performance gate, bounded private acceleration only if measured |
| Exact pick payload exhausts memory | Per/aggregate byte caps, safe offsets, transfer, cancellation, disposal audits |

| Section view changes model meaning | Display-only label, renderer/session ownership, export/source invariants |
| Recovery becomes a second authoritative database | Ordinary `.wcad` bytes, explicit Restore, existing reader, one project/two generations |
| Interrupted recovery overwrites the only copy | Validate new generation before publishing; retain prior generation |

## Plan Review Record

The proposed plan received a self-review against the completed V18–V21.1
contracts before being presented for implementation approval.

| Review area | Finding | Resolution in this plan |
| --- | --- | --- |
| Authority | “Exact picking” could imply an analytic B-rep ray hit or durable triangle identity | Screen hits remain display-derived; only the topology binding and OCCT measurement are exact |

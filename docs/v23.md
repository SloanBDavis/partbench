# V23 Release Plan: Current-exact command targets

Status: **Completed (2026-09-01).**

Do not reopen V22. Product SHA `64ed45c` and the V22 records stay closed.

Slices A–E landed. The named closer `pnpm smoke:v23-promotion-workflow` is

## Product goal

A V22 current-exact face or edge can be used as a real command target for
every completed collector that already accepts that kind, via the existing
V13 checkpoint/anchor path. Human UI and the connected agent use the same
CADOps. Vertices remain inspect-only.

After V23 this must be true: pointing at a current exact face or edge is not
a dead end. If the completed matrix already accepts that kind, the pick can
be promoted and consumed in one transactional Apply, including from MCP/agent
using existing batch/query seams. Do not add a modeling family.

## Why this

V22 made exact entities selectable, previewable, measurable, and recoverable.
Gate D still required an existing generated stable-ID match before a current
exact face or edge could enter a collector. Unmatched exact local IDs stayed
inspect-only. That is the bottleneck. Assemblies, drawings, WebGPU, natural
language, hosted MCP, and new feature families are architecture later, not
V23.

## Binding rules

1. CADOps is the center. Cad-core owns eligibility, transactions, and
   semantic diffs. Browser and geometry own current exact evidence.
2. Universal selection is not universal commandability. Unlisted kind/action
   pairs stay inspect-only or blocked with a structured reason.
3. Reuse the V22 frozen collector inventory. Do not widen a Must row.
4. Promotion is the existing V13 path: `topology.checkpoint.create` plus
   `topology.anchor.create` (via `topology.anchorCreationPlan` when that
   query already plans the batch), then the consuming feature op, in one
   Apply. Selection, hover, and measurement still submit no CADOps.
5. Raw exact local IDs and signatures never enter commands, diffs, JSON,
   `.wcad`, agents/MCP, or visible text. Durable identity is the public
   topology-anchor ID after promotion.
6. Approval modes stay `manualApproval` and `approveAll`. No third mode, no
   agent file authority, no hosted transport, no NL parser.
7. Do not add a workspace package, production dependency, project schema, or
   `.wcad` version unless promotion cannot persist on existing V13/V18
   topology-anchor and checkpoint records. Slice A must prove that before
   anyone adds source shape.
8. V21.1 gzip ceilings and production-browser gauntlets are not gate closers.

## Frozen collector × kind matrix

Copied from [`docs/archive/v22-implementation-dag.md`](./archive/v22-implementation-dag.md)
Frozen Collector Handoff Inventory. V23 changes only the promotion rule for
face and edge rows: a current exact entity of that kind may be minted as a
V13 topology anchor even when it has no generated stable ID, then consumed
by that collector if cad-core already accepts the kind and the existing
planar/linear/lifecycle checks pass.

| Kind | Existing collector | Existing durable form | Existing consuming CADOps | V23 |
| --- | --- | --- | --- | --- |
| Body | Extrude add/cut target | `targetBodyId` or the completed body-anchor row | `feature.extrude` | Keep. Body picks already command. Not a V23 promotion row. |
| Body | Hole target | `targetBodyId` or existing `targetTopologyAnchorId` | `feature.hole`, `feature.updateHole` | Keep. Body, not face. Hole sketches that need a face use sketch-on-face. |
| Body | Linear/circular pattern or mirror seed | `seedBodyId` under V21.1 policy | `feature.linearPattern`, `feature.circularPattern`, `feature.mirror` | Keep. Body, not face/edge. |
| Body | Shell target | `targetBodyId` under the exact single-solid policy | `feature.shell` | Keep. Open faces are the face row below. |
| Face | Sketch-on-face | planar generated/named/active-anchor face | `sketch.createOnFace` | Must promote unmatched current exact planar face. |
| Face | Shell open face | generated/named/active-anchor face | `feature.shell`, `feature.updateShell` | Must promote unmatched current exact face that already passes shell open-face checks. |
| Face | Mirror plane | planar generated/named/active-anchor face, optional existing offset | `feature.mirror`, `feature.updateMirror` | Must promote unmatched current exact planar face. |
| Edge | Chamfer/fillet target | eligible generated/named/active-anchor edge | `feature.chamfer`, `feature.fillet` | Must promote unmatched current exact eligible edge. |
| Edge | Linear-pattern direction / circular-pattern axis | linear generated/named/active-anchor edge or existing global axis | `feature.linearPattern`, `feature.updateLinearPattern`, `feature.circularPattern`, `feature.updateCircularPattern` | Must promote unmatched current exact linear edge. |
| Body/face/edge/vertex | Name existing generated reference | existing generated stable ID only | `reference.nameGenerated` | Keep generated-stable-ID only. Do not name arbitrary exact local IDs. |
| Vertex | Inspect/measure only | no generic anchor promotion | none | Inspect-only. Never promote. |

A non-planar face does not unlock sketch-on-face or mirror plane. A non-linear
edge does not unlock pattern direction/axis. An edge the completed fillet or
chamfer matrix rejects stays blocked. Those checks already exist. V23 does
not invent new ones and does not delete them.

The 13 body sources in the V22 selection matrix stay the fixture set. Every
face and edge Must row above is required on each source that already exposes
that collector.

## What V23 deletes

Do not park these on V24:

- assemblies, mates, drawings, PMI
- production WebGPU or a renderer rewrite
- a datum or construction-plane family (existing collectors that need a plane
  use current exact planar faces)
- splines, offsets, push/pull, direct B-rep edit, new hole families
- NL parser, hosted transport, third approval mode, agent file authority
- gzip ceilings and production-browser gauntlets as gate closers
- new workspace package, production dependency, or `.wcad` version unless
  slice A proves existing V13/V18 records cannot persist the promotion
- widening a completed operation row
- replaying V22 gates A–I or V7–V21.1 gauntlets
- making vertices commandable
- a second query seam beside `selection.referenceCandidates`

## Keep from V22

Selectable, previewable, measurable, recoverable exact single-part CAD.
Keyboard-complete paths. Startup deferral. No private IDs in UI. Four V22
product smokes as passed history. Canvas 2D. `web-cad.project.v22` and
`partbench.wcad.v2` unless slice A proves a persist gap.

## Definition of done

V23 is complete only when:

1. Every face and edge Must cell in the frozen matrix promotes an unmatched
   current exact entity and consumes it in one Apply, in the running app and
   in the named closer.
2. Vertices remain inspect-only.
3. Unlisted kind/action pairs stay inspect-only or blocked with a structured
   reason.
4. Human UI and MCP/agent submit the same CADOps.
5. No new modeling family, operation row, schema, `.wcad` version, workspace
   package, production dependency, renderer, approval mode, or agent file
   authority, unless slice A recorded a persist gap and this plan was amended
   before that change.
6. V22 behavior is unreopened: selection, preview, measure, and recovery stay
   closed.

End of proposed V23 release plan.

# V26 Release Plan: Assemblies

Status: **In progress.**

Do not reopen V22–V25. Do not invent V27.

Product toolkit SHA stays `a40c3e8`. Use/UI infra tip is `03fa944` until a V26
slice lands. Schema stays `web-cad.project.v22` / `partbench.wcad.v2` until
slice A proves a persist gap.

## Product goal

After V26, a person or the connected agent can build a multi-part assembly from
completed exact solids: insert part instances, constrain them with a short mate
set, see the assembly tree, and save/load through existing `.wcad` / project
schema (bump only if you prove persist needs it). Same CADOps for UI and MCP.
No new MCP tool unless `cad.batch` cannot express it.

## Must

1. **Part definition vs instance.** One completed solid (or saved part) can have
   many instances with transforms. Instancing, not duplicated B-rep per bolt.
2. **Mate set (all Must):** coincident planes, concentric axes, distance offset,
   fixed/ground. Structured fail when underconstrained or conflicting. Do not
   invent a full kinematics solver.
3. **Assembly tree** in the workbench (instances, mates, suppress). Selection of
   an instance is not selection of the definition's internal faces unless the
   collector says so.
4. **Insert / replace / delete** instance. Edit mate. Same CADOps for human Apply
   and agent batch.
5. **Exact display of instances** (reuse V21 exact pipeline per definition;
   instances are transforms). Pick/measure on assembly instances at least at
   body level; face/edge pick on instances if V22/V23 path extends cheaply —
   do not block the release on full subentity pick if body-level + tree
   selection ships.
6. **Scenarios:** two-part coincident stack, concentric pin-in-hole (or
   shaft-in-bore), distance mate, fixed root. Named closer + `smoke:ui` engine +
   Use path for at least one mate Apply in Chrome (`docs/verification.md`).

## Why this

V25 closed the single-part toolkit. Assemblies were always later in
architecture; now they are the user goal. One release.

## Binding rules

1. CADOps is the center. Human UI and the connected agent submit the same batch.
   Do not add an MCP tool unless `cad.batch` cannot express the ops.
2. Reuse V13 checkpoint/anchor plus V23 promotion plus V25 single-part toolkit.
3. Schema / `.wcad` bump only with persist proof in this plan / slice A.
   Until then stay `web-cad.project.v22` / `partbench.wcad.v2`.
4. Universal selection is not universal commandability.
5. Approval modes stay `manualApproval` and `approveAll`.
6. Vertices stay inspect-only.
7. Do not add a workspace package or production dependency unless this doc
   names it.
8. Elon: question, delete, then build.

## Frozen matrix (starting facts)

Today (tip `03fa944`, toolkit SHA `a40c3e8`):

- No assembly document, no part-instance CADOps, no mates, no assembly tree.
- Viewport candidate types already reserve `assemblyPath` / `instancePath` as
  private future context — do not treat that as a shipped assembly.
- `scene.updateTransform` is display-only and is not a mate.
- `feature.align` is a single-body move, not an assembly mate.

### Mate × CADOps matrix (V26)

| Mate / op | Why missing | Consumed by |
| --- | --- | --- |
| coincident planes | no mate family | instance pose solve |
| concentric axes | no mate family | pin-in-hole / shaft-in-bore |
| distance offset | no mate family | spaced faces |
| fixed / ground | no mate family | root instance |

Plus ops for: assembly create (or document host), instance insert / replace /
delete, mate create / edit / delete, suppress if needed for tree.

### Frozen CADOps set (verify against cad-protocol style before inventing)

Keep them CADOps, not a new MCP tool. Naming follows existing
`family.verb` / `family.verb.sub` style (`feature.align`, `datum.axis.create`,
`scene.updateTransform`). Frozen set for V26:

| Op | Role |
| --- | --- |
| `assembly.create` | Create / host an assembly document (or prove an existing document host is enough in slice A) |
| `assembly.instance.insert` | Insert a part definition as an instance with an initial transform |
| `assembly.instance.replace` | Replace an instance's definition |
| `assembly.instance.delete` | Delete an instance |
| `assembly.instance.suppress` | Suppress / unsuppress for the tree (only if the tree Must needs it) |
| `assembly.mate.create` | Create a mate; `kind` enum: `coincident` \| `concentric` \| `distance` \| `fixed` |
| `assembly.mate.edit` | Edit an existing mate (refs, distance, kind fields) |
| `assembly.mate.delete` | Delete a mate |

Do not invent a second mate family or a kinematics solver op. Structured fail
codes for underconstrained and conflicting mate sets land with the mate slices.
Confirm exact string names against `packages/cad-protocol` before implementation;
do not diverge from this frozen set without updating this plan.

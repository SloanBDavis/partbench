## Product goal

After V26, a person or the connected agent can build a multi-part assembly from
completed exact solids: insert part instances, constrain them with a short mate
set, see the assembly tree, and save/load through existing `.wcad` / project
schema (bump only if you prove persist needs it). Same CADOps for UI and MCP.
No new MCP tool unless `cad.batch` cannot express it.

## Must

1. **Part definition vs instance.** One completed solid (or saved part) can have
   many instances with transforms. Instancing, not duplicated B-rep per bolt.
2. **Mate set (all Must):** coincident planes, concentric axes, distance offset,
   fixed/ground. Structured fail when underconstrained or conflicting. Do not
   invent a full kinematics solver.
3. **Assembly tree** in the workbench (instances, mates, suppress). Selection of
   an instance is not selection of the definition's internal faces unless the
   collector says so.
4. **Insert / replace / delete** instance. Edit mate. Same CADOps for human Apply
   and agent batch.
5. **Exact display of instances** (reuse V21 exact pipeline per definition;
   instances are transforms). Pick/measure on assembly instances at least at
   body level; face/edge pick on instances if V22/V23 path extends cheaply —
   do not block the release on full subentity pick if body-level + tree
   selection ships.
6. **Scenarios:** two-part coincident stack, concentric pin-in-hole (or
   shaft-in-bore), distance mate, fixed root. Named closer + `smoke:ui` engine +
   Use path for at least one mate Apply in Chrome (`docs/verification.md`).

## Why this

V25 closed the single-part toolkit. Assemblies were always later in
architecture; now they are the user goal. One release.

## Slice A progress (persist + definition/instance)

Status: **landed on main; V26 closed in slice H.**

### Schema / `.wcad` bump proof — **not required**

Slice A persists assemblies as an **optional additive** `document.assemblies[]`
field on the existing `web-cad.project.v22` document snapshot (same pattern as
optional `datums[]`). Instances are transforms that reference one definition
body id; they do not invent new bodies or duplicate B-rep.

Proof:

1. Create assembly + insert ≥2 instances of one completed solid → export project
   JSON. Assemblies ride as optional `document.assemblies` (like `datums`). A
   simple solid may remain on an older supported project schema (e.g. v16);
   export does **not** invent `web-cad.project.v23` / `v26`.
2. Import the same bytes → `project.structure` still shows **one body definition**,
   **two instances**, shared `definition.bodyId`.
3. Package version stays `partbench.wcad.v2` (no package bump). Current product
   schema identity remains `web-cad.project.v22` / `partbench.wcad.v2`.

Therefore **no schema / `.wcad` bump** for slice A.

### Frozen CADOps confirmed

Names match `packages/cad-protocol` style (`family.verb` / `family.verb.sub`):

| Op | Role |
| --- | --- |
| `assembly.create` | Host an assembly document |
| `assembly.instance.insert` | Insert a definition ref + initial transform |

### Modeling

- **Definition:** `{ kind: "body", bodyId }` — a completed exact solid already in
  the document. Instancing does not copy the solid.
- **Instance:** `{ id, name, definition, transform }` under one assembly.
- **Assembly:** `{ id, name, instances[] }` stored on the document.

### Scenario

`scenarios/v26-definition-instance.json` — create, insert two instances with
different transforms, persist round-trip, assert two instances / one definition /
one body. Do **not** add `smoke:v26-assemblies` yet.

## Slice E progress (distance offset mate)

| Op | Role |
| --- | --- |
| `assembly.mate.create` | Slice E adds `kind: "distance"` (plane–plane separation) |

Reuse A–D: `assembly.create`, `assembly.instance.insert`, fixed + coincident + concentric mates, assemblies tree.
Schema stays `web-cad.project.v22` / `partbench.wcad.v2`.

### Modeling

- **Distance offset:** `{ kind: "distance", primary, secondary, distance }` under `assembly.mates[]`.
  Each side is `{ instanceId, plane: XY|XZ|YZ, offset?, flip? }` in definition space; `distance` is the
  signed separation along the stationary plane normal after pose solve.
- **Pose:** one of the two instances must already be fixed/grounded; the other
  instance moves so the planes are parallel at the given separation (reuse
  plane–plane rotation + normal translation). Not a full kinematics solver.
- **Structured fail codes (grown in slice E):** `ASSEMBLY_MATE_UNDERCONSTRAINED`
  when neither instance is fixed; `ASSEMBLY_MATE_CONFLICTING` when both are fixed.
  Coincident / concentric / distance all use these codes (same structured fields as
  the prior `INVALID_OPERATION` pattern: path / expected / received).

### CADOps

| Op | Role |
| --- | --- |
| `assembly.instance.replace` | Replace an instance's definition (keep id/name/transform) |
| `assembly.instance.delete` | Delete an instance; cascade-delete mates that reference it |
| `assembly.mate.edit` | Edit an existing mate (refs, distance, kind fields); re-solves pose |
| `assembly.mate.delete` | Delete a mate (poses left as last solved) |

`assembly.instance.suppress` not required for the tree Must yet (instances + mates already project).
Schema stays `web-cad.project.v22` / `partbench.wcad.v2`.

### Modeling

- **Replace:** swap `definition.bodyId` on an existing instance; no new body, no transform reset.
- **Delete instance:** remove instance; mates whose primary/secondary/fixed instanceId
  references it are cascade-deleted and appear in `matesDeleted`.
- **Edit mate:** same payload shapes as create, keyed by `mateId`; coincident /
  concentric / distance re-solve pose; semantic diff uses `matesModified`.
- **Delete mate:** remove mate record; do not reverse prior pose.

## Slice G progress (exact display + body pick)

Status: **landed on main; V26 closed in slice H.**

### Exact display

Reuse the V21 exact pipeline **per definition body**. Assembly instances do not
retessellate: each instance is a display mesh that shares the definition
`vertices`/`indices` and applies the instance `transform`. Mesh ids match the
assembly tree key (`assembly-instance:{assemblyId}:{instanceId}`).

Schema stays `web-cad.project.v22` / `partbench.wcad.v2`.

### Body-level pick / measure

- Viewport pick of an instance mesh selects the **instance** (tree), not
  definition faces.
- Body measure/inspect uses the shared definition body (volume/area unchanged;
  instances are transforms).
- Face/edge/vertex pick on instances is **deferred** — V22/V23 exact subentity
  pick does not thread instance context cheaply enough; do not block the release.

### Proof

Focused tests: `assemblyInstanceExactDisplay.test.ts` (≥2 instances, shared
definition, different transforms + body pick target) and viewport interaction
contract body-level instance context. Do **not** add `smoke:v26-assemblies` yet
(that is slice H).

# V21.1 Spec: Universal Downstream Bodies and Export Completion

Status: **Completed (2026-08-03).**

V21.1 is a focused follow-up to the completed V21 release. It closes the
remaining single-part usability gaps without pulling assemblies, drawings,
direct modeling, parametric STEP reconstruction, or broad format work into one
release.

The product label **V21.1** is unrelated to project schema names. This release
adds no authoritative source shape, so projects continue to use the lowest
sufficient schema through `web-cad.project.v22`; `.wcad` remains
`partbench.wcad.v2`.

There is no Stretch section. Every outcome in this document is Must unless it
is explicitly listed as a non-goal. Implementation follows the approved
[`docs/v21.1-implementation-dag.md`](./v21.1-implementation-dag.md), which
freezes the exact fixture matrix and landing order.

Final release evidence is recorded in
[`docs/v21.1-g-gate.md`](./v21.1-g-gate.md).

## Release Goal

After V21.1, the following statement must be true:

> Every active, healthy, exact-ready single-part body can be used through the
> documented hole, pattern, mirror, and shell rules without a feature-family
> recipe gap; users can recover, cache, select, and export those results through
> one truthful browser-owned workflow.

A user must be able to:

1. create a circular blind or through-all hole in either direction on every
   active exact-ready body family, including primitives, imported bodies,
   downstream results, and supported multi-solid shapes;
2. retarget an existing hole transactionally to another eligible body without
   changing the hole result body ID;
3. use every active exact-ready body as a linear/circular pattern or mirror
   seed, including imported and recursive downstream results;
4. submit every active exact-ready single-solid body to shell feasibility,
   using current topology references for optional open faces, and receive
   either a valid exact result or a structured no-commit geometry failure;
5. see the same eligibility, progress, failure, topology, mass, display, and
   export state in Solid, Project, Inspect, and connected-agent surfaces;
6. explicitly export all currently ready bodies without manually clearing a
   long blocked-body list, while retaining the strict V21 Export-all action;
7. reopen unchanged work faster through a bounded, validated, derived-only
   exact-artifact cache where OPFS is available;
8. understand when JSON is not self-contained and recover matching checkpoint
   payloads from a user-selected `.wcad` file;
9. let a connected local agent request a browser STEP download through the two
   existing V20 approval modes without returning file bytes or paths; and
10. export the full 256-body protocol limit in a real production-browser
    workflow with bounded memory, responsive progress, cancellation, and exact
    round-trip evidence.

## Gap Ledger

| Gap after V21 | V21.1 disposition |
| --- | --- |
| Imported bodies cannot be direct hole targets | Must: included in universal hole target support |
| Hole target support depends on rectangle/circle extrude ancestry | Must: replace ancestry policy with exact-body operand policy |
| Existing holes cannot change targets | Must: additive transactional retarget support |
| Pattern/mirror/shell validators and supported geometry matrices disagree | Must: one exhaustive source policy and exact-artifact execution path |
| Export-all is intentionally blocked by one unhealthy active body | Retain Export-all; add an explicit reviewed ready-subset action |
| Exact artifacts rebuild every browser session | Add a bounded derived-only OPFS cache with strict validation and cold fallback |
| JSON cannot carry authoritative imported/topology checkpoint payloads | Keep JSON source-only; add portability status and exact `.wcad` payload recovery |
| Agents can plan export but cannot ask the browser to download it | Add approval-bound browser export request; agents still receive no bytes or paths |
| Real-browser near-limit evidence covers 16 rather than 256 bodies | Must: run the production browser at exactly 256 selected bodies |
| STEP does not preserve editable Partbench history, sketches, IDs, or stable topology IDs | Route to **Parametric Interchange and Native Identity** |
| Assemblies, BOMs, mates, hierarchy, and assembly STEP | Route to **Assemblies and Instance Interchange** |
| Direct edit and datum authoring | Route to **Direct Modeling and Datums** |
| Drawings, PDF, DXF, and SVG workflows | Route to **Drawings and 2D Interchange** |

| Exact subentity highlight/picking overhaul and persisted measurements | Route to **Exact Viewport Interaction** |
| Hosted transport or raw agent file/path authority | Route to **Hosted Agent and File Authority** only if separately approved |

The routed successor names reserve problem boundaries only. They do not approve
scope, ordering, schemas, packages, dependencies, or implementation.

## Non-Negotiable Architecture

1. `CadDocument`, transaction history, and existing checkpoint source records
   remain authoritative. Exact artifacts, cache entries, readiness, preflights,
   export jobs, and recovered package bytes remain derived or app-owned.
2. Cad-core decides body lifecycle, dependency legality, operation eligibility,
   consumption, source identity, semantic diffs, and undo/redo behavior.
3. Browser-owned checkpoint bytes, OPFS records, B-rep bytes, file handles,
   downloads, and OCCT execution never enter cad-core or authoritative source.
4. Geometry construction remains behind geometry-kernel, geometry-worker, and
   occt-wasm. React and the renderer do not infer downstream command support.
5. V21.1 reuses V21's current exact-body resolver and identity-bound artifact.
   It does not add another feature-to-shape recipe mapper.
6. A verified exact-body artifact is the sole geometry operand for newly
   widened hole, pattern, mirror, and shell execution.
7. Source-level eligibility is necessary but not sufficient. Geometry-dependent
   feasibility uses the same browser/worker preflight for human and connected
   agent execution before a command commits.
8. V21 source-identity checks, staleness rules, all-or-nothing STEP semantics,
   resource caps, and browser file ownership remain binding.
9. The V20 approval vocabulary remains exactly `manualApproval` and
   `approveAll`. V21.1 adds an approved action, not a third mode or per-tool
   policy system.
10. V21.1 adds no production dependency, workspace package, geometry engine,
    generic artifact registry, export framework, or background service.

## Binding Decisions

### 1. Use One Verified Exact-Body Operand

V21 already resolves every completed body through one exact B-rep artifact.
V21.1 promotes that artifact into the universal internal operand for downstream
whole-body operations.

The geometry-kernel/worker contract may use existing naming conventions, but
its semantics are equivalent to:

```ts
interface ExactBodyArtifactLeaf {
  readonly kind: "bodyArtifact";
  readonly bodyId: BodyId;
  readonly bodySourceIdentitySignature: string;
  readonly sourceCacheKeySha256: string;
  readonly brepByteLength: number;
  readonly brepSha256: string;
  readonly brepBytes: Uint8Array;
  readonly topologySignature: string;
  readonly shapePolicy:
    | "singleSolid"
    | "singleShapeOneOrMoreSolids";
}

type ExactArtifactDownstreamSource =
  | {
      readonly kind: "artifactHole";
      readonly target: ExactBodyArtifactLeaf;
      readonly tool: HoleToolSource;
    }
  | {
      readonly kind: "artifactLinearPattern";
      readonly seed: ExactBodyArtifactLeaf;
      readonly direction: readonly [number, number, number];
      readonly spacing: number;
      readonly instanceCount: number;
    }
  | {
      readonly kind: "artifactCircularPattern";
      readonly seed: ExactBodyArtifactLeaf;
      readonly axis: GeometryKernelAxisFrame;
      readonly totalAngleDegrees: number;
      readonly instanceCount: number;
    }
  | {
      readonly kind: "artifactMirror";
      readonly seed: ExactBodyArtifactLeaf;
      readonly plane: GeometryKernelPlaneFrame;
      readonly includeOriginal: boolean;
    }
  | {
      readonly kind: "artifactShell";
      readonly target: ExactBodyArtifactLeaf;
      readonly wallThickness: number;
      readonly openFaces: readonly ExactTopologyFaceRef[];
    };
```

These are internal, transferable geometry contracts. Public protocol evidence
may contain bounded hashes, identities, counts, and status but never B-rep
bytes, cache keys usable as storage handles, OCCT handles, or OPFS paths.

The operand builder must:

- resolve source policy before geometry work;
- build or validated-cache-read each dependency artifact once per generation;
- verify body identity, source identity, byte length, hash, shape policy, and
  topology signature before use;
- reject dependency cycles and plans over the existing 4,096-node cap;
- preserve source order where the operation has ordered inputs;
- derive result B-rep, metadata, topology, signatures, references, display, and
  export evidence from one result shape lifetime; and
- release dependency bytes and OCCT objects on success, failure, cancellation,
  staleness, replacement, or worker disposal.

No operation may fall back to a narrower recipe because an artifact is missing.
It reports the shared exact-result blocker and leaves source unchanged.

Result shape policy is derived from the operation rather than hard-coded by
feature kind: a hole inherits `singleSolid` versus
`singleShapeOneOrMoreSolids` from its target, pattern and mirror allow one or
more solids, and shell requires and returns one solid. The V21 release fixture
policy must be amended accordingly rather than leaving every hole result
classified as `singleSolid`.

### 2. Total Hole Support Means Total Target Coverage

“Total hole support” in V21.1 means the existing circular `feature.hole`
operation can target every active exact-ready body family. It does not add
counterbores, countersinks, threads, tapered holes, arbitrary profile cuts, or
a new hole wizard.

The retained tool matrix is:

| Hole input | V21.1 support |
| --- | --- |
| Profile | One non-construction sketch circle |
| Depth | Positive finite blind depth or through-all |
| Direction | Positive or negative |
| Sketch plane | XY, XZ, or YZ, including existing valid face attachment |
| Target | Any active, healthy, exact-ready semantic body |
| Target solids | One or more solids in one validated exact shape |

The exhaustive target matrix is:

| Target origin | Create hole | Retarget existing hole | Exact/display/export parity |
| --- | --- | --- | --- |
| Box, cylinder, sphere, cone, torus | Must | Must | Must |
| Entity/wire/region extrude and supported add/cut result | Must | Must | Must |
| Entity/wire/region revolve | Must | Must | Must |
| Sweep and loft in completed matrices | Must | Must | Must |
| Existing hole result | Must | Must | Must |
| Chamfer or fillet result | Must | Must | Must |
| Linear/circular pattern result | Must | Must | Must |
| Mirror result | Must | Must | Must |
| Shell result | Must | Must | Must |
| Imported STEP solid or compound | Must | Must | Must |
| Checkpoint-backed downstream result | Must | Must | Must |
| Supported multi-solid/compound shape | Must | Must | Must with retained multi-solid warning |
| Consumed, stale, failed, repair-needed, missing-payload, or unsupported body | Blocked | Blocked | Never fabricated |

Whole-body selection uses the semantic `bodyId`. It does not require a face
anchor merely to identify the body. A sketch attached to a face still requires
the existing generated, named, or topology-anchor face proof. Imported and
checkpoint-backed targets must have current validated payload evidence before
preflight or commit.

For a multi-solid target, the circular tool is applied to every solid it
intersects. Non-intersected solids remain unchanged and selected-body identity
continues to describe the one result shape. The operation fails atomically when:

- the tool intersects no target solid;
- the boolean returns a null, empty, invalid, or non-finite result;
- the result violates the target's validated solid policy;
- any dependency identity changes during preflight or commit; or
- resource limits are exceeded.

`feature.updateHole` gains optional `targetBodyId` and
`targetTopologyAnchorId` fields with the same mutual-exclusion and validation
rules as create. Retargeting is one transaction:

1. validate the new target and reject self/descendant/cyclic dependencies;
2. exact-preflight the existing circle tool against the new target;
3. reactivate the old target body;
4. consume the new target body;
5. retain the hole feature ID and result body ID;
6. invalidate the result's derived/topology evidence; and
7. emit complete feature, body-lifecycle, reference, rebuild, and topology
   semantic diffs.

Undo and redo must restore both targets' lifecycle and the corresponding exact
result. A failed, cancelled, or stale retarget changes nothing.

### 3. Pattern and Mirror Accept Every Exact-Ready Body

Linear pattern, circular pattern, and mirror seed policy becomes:

```text
active semantic body
+ current healthy source/dependencies
+ current verified exact artifact with one or more solids
+ no consumption or dependency cycle
= eligible seed
```

This includes primitives, revolves, sweeps, lofts, holes, edge finishes,
imports, patterns, mirrors, shells, and checkpoint-backed downstream results.
Recursive downstream use is supported when the source dependency graph remains
acyclic and within instance, graph, artifact, and output caps. New pattern
create/update commands are limited to 4,096 instances per feature; historical
projects remain readable, but an over-limit pattern is blocked from rebuild or
downstream exact use until its count is reduced.

Current pattern direction, circular axis, mirror plane, instance transform,
include-original, consumption, and one-public-result-body semantics remain
unchanged. Pattern and mirror may return one shape containing multiple solids;
the existing warning and exact-export behavior remain binding.

The implementation must remove or stop consulting extrude-family-only seed
unions in production validation, display, exact metadata, artifact, and export
paths. Compatibility readers may retain old types only where public historical
payloads require them.

### 4. Shell Accepts Every Exact-Ready Single Solid

Shell target policy becomes:

```text
active semantic body
+ current healthy source/dependencies
+ current verified exact artifact containing exactly one solid
+ current resolvable open-face references, when any are requested
= eligible shell target
```

Closed shell is available for every qualifying single solid. Open shell uses
generated, named, or topology-anchor face references resolved against the
target artifact's current topology snapshot. The Project/Solid chooser must
offer a keyboard-accessible face list even where viewport face picking remains
outside V21.1.

Multi-solid shell remains blocked because “shell the compound” has no single
unambiguous wall/open-face result policy. Users may shell an explicitly modeled
single-solid body before patterning or combining it. The UI and agent query
must report `SHELL_TARGET_MULTI_SOLID_UNSUPPORTED`, not a worker crash.

Wall-thickness feasibility remains geometry-dependent. Null, inverted,
self-intersecting, or invalid shell results fail preflight and do not commit.

### 5. One Exhaustive Downstream Policy Drives Every Surface

Cad-core adds one compile-time exhaustive operation policy over every
`CadBodySource["type"]` for:

- hole target;
- pattern seed;
- mirror seed; and
- shell target.

The policy expresses source/lifecycle eligibility and required shape policy,
not geometry recipes. Runtime matrix tests fail if a new body source is added
without all four decisions.

The browser combines that policy with V21 current exact-result evidence and
geometry preflight. Solid, Project, Inspect, selection/reference readiness,
display, topology, mass properties, STEP planning, agent queries, human
commands, and connected agent commits must agree. A successful OCCT call cannot
override a source-policy blocker, and an eligible source cannot be rejected
merely because an old recipe union does not name its feature family.

Human and connected-agent creates/updates use the same app-owned exact
preflight before the same CADOps transaction commits. The in-memory adapter,
which has no browser/OCCT runtime, may dry-run source eligibility but must report
that exact preflight is unavailable rather than claiming a widened command can
commit safely.

### 6. Add a Derived-Only Exact Artifact Cache

V21.1 adds one optional OPFS cache for current exact B-rep artifacts. It exists
to reduce unchanged warm-open rebuild work; it is never source authority and is
not required for correctness.

The cache key includes at least:

- canonical body source identity signature;
- exact source cache-key SHA-256;
- geometry-kernel protocol version;
- OCCT/WASM build fingerprint;
- artifact writer/format version; and
- shape policy.

A cache entry contains only private derived evidence:

- B-rep bytes, byte length, and SHA-256;
- topology signature and source kind;
- shape policy; and
- bounded cache bookkeeping such as byte size and last-access order.

On a hit, the worker must length/hash-check and parse the B-rep to a non-null
shape, recompute current metadata/topology from that shape, and verify its
topology signature before reporting ready. Stored metadata alone never
authorizes readiness.

Cache behavior is:

- best-effort cold rebuild when OPFS is absent, denied, full, corrupt, or
  unavailable;
- 128 MiB maximum per entry and 512 MiB maximum retained cache bytes;
- deterministic least-recently-used eviction using the existing cache/storage
  patterns rather than a new cache framework;
- write only after the artifact and source identities are still current;
- ignore and remove corrupt or version-mismatched entries;
- never satisfy a missing authoritative imported/topology checkpoint payload;
- never change source identity, history, redo, dirty state, schema, `.wcad`, or
  export plan identity; and
- expose one Project/Storage action to clear derived exact data.

Warm-cache release evidence must prove feature reconstruction and B-rep
serialization are skipped on valid hits. Wall-clock timings are recorded, but
correctness is not conditional on hardware-specific speedup.

### 7. Keep Export-All Strict and Add an Explicit Ready Subset

The existing **Export all bodies** action retains V21 all-or-nothing semantics.
It continues to fail rather than silently omit a blocked active body.

V21.1 adds **Export N ready bodies** when at least one active body is ready and
at least one other active body is not. Before execution, the panel displays:

- the exact ordered body IDs and names that will be included;
- every excluded body and its current root blocker;
- AP242, units, name preservation, and all-or-nothing wording for the new
  explicit subset; and
- a link to the existing ordered chooser for manual changes.

Activating the action creates an explicit `bodyIds` plan in canonical active
body order. It does not reinterpret an omitted list, mutate selection, remember
a policy, or change later Export-all behavior. Any included body becoming stale
or blocked before download fails the subset atomically.

### 8. Make JSON Portability and Recovery Explicit

JSON remains a source-only diagnostic/interchange view and never embeds B-rep,
STEP, OPFS, or checkpoint payload bytes. `.wcad` remains the portable Partbench
project package.

Project/File adds a portability projection:

```ts
type ProjectPortabilityStatus =
  | { readonly status: "portable-json" }
  | { readonly status: "wcad-required"; readonly checkpointIds: readonly string[] }
  | { readonly status: "payload-missing"; readonly checkpointIds: readonly string[] };
```

For a checkpoint-backed project:

- `.wcad` is the primary download action;
- JSON remains available as **Download source-only JSON** with visible copy
  that it cannot reopen imported/checkpoint-backed geometry by itself;
- Open JSON lists every missing checkpoint rather than collapsing them into one
  generic failure; and
- **Recover payloads from .wcad** accepts one user-selected package and imports
  only payloads whose manifest ID, body ID, feature ID, byte length, SHA-256,
  topology signature, and source identity match the open project.

Recovery hydrates app-owned payloads and enables a new `.wcad` save. It does not
replace document source, merge another project, invent geometry, use the exact
artifact cache, or enter history. Recovery is all-or-nothing: any requested
mismatch imports nothing and returns structured per-checkpoint diagnostics.
Re-importing a STEP file as new source retains its existing explicit project
command semantics and is not recovery.

### 9. Let Agents Request Browser-Owned Export

V21.1 adds one MCP action tool, named
`cad.project_request_exact_export`, with a bounded request:

```ts
interface CadAgentExactExportRequest {
  readonly requestId: string;
  readonly selection:
    | { readonly mode: "all" }
    | { readonly mode: "readySubset" }
    | { readonly mode: "bodyIds"; readonly bodyIds: readonly BodyId[] };
  readonly expectedSourceIdentity?: WcadSourceIdentity;
}
```

The action reuses the existing browser exact-export planner and executor. It
does not accept a path, directory, file handle, arbitrary filename, MIME type,
format plugin, or bytes.

The public tool name is `cad.project_request_exact_export`. `readySubset`
derives an explicit canonical-order plan: when all active bodies are ready it
contains all of them, and when none are ready it returns blockers without a
proposal or download request.

V20's private connected adapter port gains one fifth typed operation for this
specific action. It remains a closed typed union, not a generic RPC registry.

Approval behavior is:

| Request | `manualApproval` | `approveAll` |
| --- | --- | --- |
| Invalid or blocked plan | Return diagnostics; no proposal | Return diagnostics; no download |
| Valid exact export | Show one export proposal; Approve or Reject | Execute browser download immediately |
| Another commit/export proposal pending | `AGENT_APPROVAL_BUSY` | Not applicable |
| Source changes before approval/download | `AGENT_PROPOSAL_STALE` or `EXPORT_SOURCE_CHANGED` | `EXPORT_SOURCE_CHANGED` |

There remains one pending proposal union for commit or export, not two queues.
The Agent page proposal shows body names/order/count, AP242, units, plan/source
identity, warnings, blockers, and the fact that approval triggers a local
browser download. Switching to Approve everything must update its confirmation
copy to include valid agent-requested downloads for that browser session.

The tool call waits for approval, STEP completion, and the browser download
request. Anchor-based browser downloads expose no completion callback, so the
success status is truthfully `downloadRequested`, not `downloaded`; writer,
source, Blob, and request failures before the click remain observable. Its
response contains only bounded metadata such as plan identity, selected body
IDs/count, schema, units, artifact byte length/SHA-256, and
`downloadRequested`, `rejected`, `cancelled`, `stale`, or `failed`. It returns
no STEP bytes, Blob, object URL, browser handle, filename path, OPFS path, or
download-directory information.

Human Cancel, worker restart, browser download failure, agent disconnect, New,
Open, undo, redo, source edits, and approved agent edits retain the V21 atomic
failure rules. Reload/disconnect returns approval mode to Manual as in V20.

### 10. Resource, Failure, and Security Limits Remain Binding

V21 limits remain the default unless this release narrows them:

- 256 explicitly selected bodies per export;
- 4,096 exact dependency graph nodes;
- 128 MiB per B-rep artifact or cache entry;
- 512 MiB aggregate artifacts per export;
- 512 MiB final STEP output;
- finite numeric geometry/metadata only; and
- no duplicate body IDs or dependency cycles.

V21.1 additionally requires:

- one dependency artifact build or valid cache read per body per generation;
- one active exact export job and one pending agent proposal at a time;
- at most 4,096 instances in a newly created or updated pattern feature;
- cancellation checks between dependency bodies and before every cache write,
  STEP write, and download;
- source identity verification before preflight, after dependency build, after
  result build, after STEP write, and immediately before download;
- untrusted cache/recovery B-rep parsing only inside OCCT/WASM;
- temporary virtual files and object URLs unlinked/revoked in `finally` paths;
- no main-thread base64 encoding or decoding; and
- no cache, recovery, or agent action that can read an arbitrary local path.

The minimum new diagnostic meanings are:

```text
HOLE_TOOL_NO_INTERSECTION
HOLE_RESULT_INVALID
SHELL_TARGET_MULTI_SOLID_UNSUPPORTED
EXACT_CACHE_ENTRY_INVALID
CHECKPOINT_PAYLOAD_RECOVERY_MISMATCH
```

Existing exact diagnostics must be reused for missing/stale/failed artifacts,
source changes, cancellation, resource limits, writer failure, and agent
approval states. A new code is permitted only when none of those meanings is
accurate.

### 11. No Authoritative Storage Version Change

V21.1 changes command eligibility and adds optional fields to an update command;
it does not require a new stored feature shape:

- `FeatureUpdateHoleOp` gains optional target fields;
- stored `HoleFeature`, pattern, mirror, and shell records retain their existing
  body reference shapes;
- V1-V22 JSON remains readable;
- minimum-schema export remains unchanged;
- `.wcad` remains `partbench.wcad.v2`;
- exact cache records are private, versioned, derived OPFS data;
- recovered payloads use existing `.wcad` checkpoint manifest entries; and
- agent proposals/jobs remain session-only.

Historical commands, diffs, JSON, CBOR, `.wcad`, and agent audit records remain
readable. V21.1 does not rewrite old narrow-source commands or claim that an old
failed operation had succeeded.

## Public and Internal Contract Changes

### Cad Protocol

Additive work:

- optional hole retarget fields on `feature.updateHole`;
- exhaustive downstream operand capability/readiness evidence;
- portability status and per-checkpoint recovery diagnostics;
- explicit ready-subset plan metadata;
- agent exact-export request/result metadata without bytes; and
- cache status/count/byte summaries without private cache keys or paths.

Trust-boundary validators reject mixed hole target fields, duplicate/over-limit
body selections, unknown selection modes, malformed identities/hashes/counts,
non-finite values, extra action fields, and any public artifact-byte claim.

### Cad Core

Cad-core owns:

- exhaustive operation policy for every body source;
- active/consumed and dependency-cycle validation;
- hole retarget lifecycle and semantic diffs;
- deterministic ready-subset body ordering from caller-supplied current exact
  evidence;
- source/body/plan identity; and
- public readiness, portability, and diagnostic projection.

Cad-core never reads exact artifacts, cache records, package payload bytes,
browser state, or agent download state.

### Web App

The app owns:

- artifact dependency orchestration and shared preflight for human/agent work;
- current exact evidence injection;
- OPFS exact cache reads/writes/eviction/clear;
- `.wcad` payload recovery and file pickers;
- ready-subset review UX;
- export proposal, progress, Cancel, Retry, Blob/download, and focus handling;
- final source checks; and
- current session-local agent action execution.

### Geometry Kernel / Worker / OCCT WASM

The geometry boundary owns:

- artifact-leaf validation and B-rep parsing;
- hole/pattern/mirror/shell exact execution from artifact leaves;
- multi-solid hole behavior;
- shell single-solid enforcement;
- feasibility, metadata, topology, references, signatures, and B-rep output
  from one shape lifetime;
- temporary-file and OCCT-object cleanup; and
- transferable ownership without detached-buffer reuse.

### Agent / MCP / Stdio

The connected stack owns one typed export-action relay in addition to the V20
four-operation port. It preserves stdio MCP, loopback authentication,
single-browser ownership, origin/host/token/path checks, the two approval modes,
and metadata-only responses.

## Implementation Slices and Gates

Implementation must follow a separate approved DAG. The required sequence is:

| Order | Slice | Required result |
| --- | --- | --- |
| 1 | A — Baseline, protocol, and frozen matrix | Clean V21 baseline; exact body-source × operation fixtures; retarget/action/cache/recovery contracts; no geometry changes |
| 2 | B — Universal exact-body operand | Artifact-leaf validation, dependency DAG, deduplication, transfer, limits, same-shape evidence, and fault cleanup |
| 3 | C — Total hole support | Every target row, multi-solid behavior, create/retarget/undo/redo, shared preflight, UI/agent parity |
| 4 | D — Pattern, mirror, and shell breadth | Every eligible source family, recursive acyclic results, shell face refs/single-solid rule, removal of recipe-gated drift |
| 5 | E — Exact cache and portability recovery | Derived OPFS cache, cold fallback, eviction/corruption, Project portability status, exact `.wcad` payload recovery |
| 6 | F — Export subset and agent action | Explicit ready subset, fifth typed relay action, two-mode approval, download/status/focus/security proof |
| 7 | G — Full-limit release proof | Exactly 256 bodies in production browser, round trips, cancellation/staleness, performance/bundle/security, V12-V21 compatibility, docs reconciliation |

Each gate requires focused tests, package typechecks, lint/format for touched
surfaces, `git diff --check`, and deletion of superseded narrow production
branches where compatibility permits.

## Performance and Bundle Gates

V21.1 retains V21's fixed gzip ceilings:

```text
critical UI JavaScript       <= 409,600 bytes
critical CSS                 <= 20,480 bytes
all non-worker UI JavaScript <= 563,200 bytes
command worker               <= 262,144 bytes
geometry worker              <= 122,880 bytes
OCCT WASM                    <= 13,808,536 bytes
```

No cap increase is approved by this spec. New Project, cache, recovery, and
agent action code must remain lazy. Empty projects and ordinary sketching must
not open OPFS or instantiate OCCT merely because V21.1 is installed.

Runtime gates require:

- interaction feedback by the next animation frame;
- no export/cache/recovery main-thread task over 50 ms in representative runs;
- zero main-thread base64 conversion;
- stale/cancelled worker/cache/action responses never apply;
- bounded memory after every terminal path;
- warm cache hits skip feature reconstruction and artifact serialization;
- exactly 256 selected bodies complete under existing byte/resource caps; and
- recorded cold/warm p50/p95 artifact, operation, STEP, recovery, eviction,
  total, byte-size, and worker-restart measurements.

Wall-clock timings are evidence, not correctness promises across hardware.

## Reserved Successor Milestones

### Parametric Interchange and Native Identity

Decide whether editable Partbench history travels as a standard AP242 construct,

### Drawings and 2D Interchange

### Format Breadth

Add measured user-driven exact/mesh formats such as IGES, STL, and 3MF one at a

### Exact Viewport Interaction

Add exact face/edge/vertex picking/highlight architecture, selection-buffer
replacement, generated vertex support, persisted measurements, section view,
and clipping without making the renderer authoritative.

### Hosted Agent and File Authority

Only if separately approved, design hosted authentication, collaboration, raw
artifact delivery, and file authority as a security release. V21.1's local
browser download action is not precedent for exposing bytes or paths.

## Risk Controls

| Risk | Control |
| --- | --- |
| “Universal” silently widens unsupported geometry | Cad-core source/lifecycle policy first; exact preflight second; committed fixture matrix |
| Recipe unions survive in one consumer | One artifact leaf for all widened operations; source-kind × consumer tests; delete superseded branches |
| Multi-solid hole behavior is ambiguous | Cut every intersecting solid, retain non-intersecting solids, require at least one changed solid |
| Hole retarget corrupts lifecycle | One transaction, cycle check, full semantic diff, undo/redo/source-identity tests |
| Recursive pattern graph explodes | 4,096-node and 4,096-instance caps, byte caps, cycle rejection, per-generation artifact deduplication |
| Shell fails late on unsuitable shapes | Single-solid policy, current face refs, exact preflight before commit |
| Cache becomes dual authority | Source identity first, parse/recompute on hit, cold fallback, no checkpoint substitution, clearable LRU |
| JSON recovery imports the wrong geometry | Exact manifest/body/feature/hash/topology/source match; all-or-nothing mismatch |
| Ready subset becomes silent omission | Separate explicit action, reviewed inclusion/exclusion list, explicit bodyIds plan |
| Agent action becomes file authority | Browser-only download, two existing modes, no caller filename/path/bytes, metadata-only result |

| Bundle grows past fixed caps | Lazy routes/cache/agent code, no dependency, existing fixed cap gate |

# V21.1 Implementation DAG: Universal Downstream Bodies and Export Completion

Status: **Approved for implementation (2026-08-02).**

This document turns [`docs/v21.1.md`](./v21.1.md) into the binding landing
order and freezes the release fixture matrix. The spec remains authoritative
for behavior, limits, non-goals, and Definition of Done. This DAG is
authoritative for dependencies, gates, and evidence.

V21.1 has no Stretch work. Slices land A-G in order. Heavy test, build, OCCT,
and browser commands run serially on the release machine. A gate cannot pass
on mocks where the spec requires real OCCT, OPFS, download, or browser proof.

## Working Rules

1. Keep every commit typed and its focused tests green.
2. Reuse V21's current exact resolver, artifacts, STEP writer, identities,
   worker, storage helpers, and V20 approval plumbing.
3. Cad-core owns source/lifecycle policy and transactions. The browser owns
   bytes, preflight, cache, recovery, jobs, and downloads.
4. One verified artifact leaf is the only widened geometry operand. Delete a
   superseded recipe branch as soon as compatibility no longer needs it.
5. Source identity is checked at every asynchronous boundary named by the spec.
6. No cache hit, OCCT success, or UI state may override a cad-core blocker.
7. No new dependency, package, schema, `.wcad` version, approval mode, generic
   registry, job framework, or file authority is permitted.
8. Record focused commands and commit IDs at every gate. Run heavy commands
   one at a time.
9. Geometry preflight and commit share the captured cad-core source-authority
   epoch. Direct cad-core execution remains source validation only; browser
   widened commits require current transient preflight proof.

## Frozen Source × Operation Policy

`CadBodySource["type"]` has 13 members at plan approval. The compile-time map
must fail when that union grows without four new decisions. Every row below is
source-eligible only while active and healthy; a current verified artifact and
the operation's required solid policy remain mandatory.

| Body source | Frozen fixture cases | Hole | Linear/circular pattern | Mirror | Shell |
| --- | --- | --- | --- | --- | --- |
| `primitiveFeature` | box, cylinder, sphere, cone, torus | one-or-more | one-or-more | one-or-more | exactly one |
| `sketchExtrudeFeature` | entity/wire/region new body and supported add/cut | one-or-more | one-or-more | one-or-more | exactly one |
| `sketchRevolveFeature` | entity/wire/one-region | one-or-more | one-or-more | one-or-more | exactly one |
| `sketchHoleFeature` | blind/through-all, both directions, recursive result | one-or-more; result inherits target policy | one-or-more | one-or-more | exactly one |
| `edgeChamferFeature` | generated/named/topology/imported edge | one-or-more | one-or-more | one-or-more | exactly one |
| `edgeFilletFeature` | generated/named/topology/imported edge | one-or-more | one-or-more | one-or-more | exactly one |
| `linearPatternFeature` | global/generated/named/topology direction, recursive | one-or-more | one-or-more | one-or-more | exactly one |
| `circularPatternFeature` | global/generated/named/topology axis, recursive | one-or-more | one-or-more | one-or-more | exactly one |
| `mirrorFeature` | standard/generated/named/topology plane, recursive | one-or-more | one-or-more | one-or-more | exactly one |
| `shellFeature` | closed and generated/named/topology open face | one-or-more | one-or-more | one-or-more | exactly one |
| `sweepFeature` | line, arc, open G1 line/arc chain | one-or-more | one-or-more | one-or-more | exactly one |
| `loftFeature` | supported separated entity sections | one-or-more | one-or-more | one-or-more | exactly one |
| `importedStepBody` | solid, compound, recovered checkpoint downstream | one-or-more | one-or-more | one-or-more | exactly one |

The following classifications are frozen for every row:

- consumed, stale, failed, repair-needed, missing-payload, unsupported,
  duplicate-owned, cyclic, over-limit, or identity-mismatched bodies block;
- hole, pattern, and mirror accept a verified shape containing one or more
  solids;
- shell accepts exactly one solid and reports
  `SHELL_TARGET_MULTI_SOLID_UNSUPPORTED` for more than one;
- optional shell faces resolve through current generated, named, or topology
  references; and
- geometry-dependent feasibility is decided by the shared worker preflight,
  never by adding family recipes to this table.

## Frozen Geometry Fixtures

The minimum real-OCCT cross-product is:

- holes: blind and through-all × positive and negative direction × every
  source row; multi-solid fixtures cover partial intersection, all-solid
  intersection, no intersection, tangency/non-volume, full removal, invalid
  result, corrupt artifact, cancellation, staleness, and caps;
- retarget: authored -> imported -> recursive downstream, plus self,
  descendant, cycle, failed/cancelled/stale preflight, undo, redo, replay, and
  save/open while feature ID and result body ID remain stable;
- patterns/mirror: every row once for linear, circular, and mirror, plus pattern
  of mirror, mirror of pattern, cycle, node/instance/artifact caps, and
  multi-solid output;
- shell: closed shell for every single-solid row, representative open shell for
  generated/named/topology face refs, infeasible thickness, invalid face,
  stale face, multi-solid rejection, and cancellation; and
- every successful widened result compares B-rep, display, metadata, topology,
  references, mass, and STEP/re-import evidence derived from the same result
  shape lifetime.

The hole tool sketch may remain attached to the old target after retargeting.
That body becomes active and remains a read-only support dependency; it is not
consumed merely because its face supports the sketch. The ordinary cycle and
current-face checks still apply.

## Slice A — Baseline, Contracts, and Policy

### A1 — Baseline

- preserve a clean V21 release baseline;
- run all eight named V21 commands serially;
- record repository test/typecheck/lint/format/build and fixed bundle ceilings;
- classify any pre-existing failure before production changes; and
- confirm no production dependency, package, schema, `.wcad` version, or
  approval-mode change.

### A2 — Additive Contracts

- add optional mutually exclusive hole retarget fields;
- add byte-free downstream readiness, ready-subset, portability/recovery,
  cache-summary, and agent request/result contracts;
- reject duplicate/over-limit selections, malformed identities/hashes/counts,
  mixed target fields, extra action fields, and public bytes/paths/handles; and
- retain V1-V22, history/diff, JSON/CBOR, `.wcad` v2, and old agent audit reads.

### A3 — One Exhaustive Cad-Core Policy

- implement the frozen 13×4 policy as one compile-time exhaustive map;
- combine it with lifecycle, dependency, cycle, and requested solid policy;
- expose the same pure projection to command validation, queries, UI, and
  adapters; and
- keep geometry feasibility and bytes out of cad-core.

### Gate A

Gate A requires the V21 baseline, protocol/core focused tests, exhaustive
matrix test, compatibility parsers, package typechecks, lint/format for touched
files, and `git diff --check`. No geometry behavior lands in Slice A.

A1-A3 and Gate A passed against implementation commit `30b7a99`; the committed
[V21.1 Gate A baseline and closure evidence](./v21.1-a-baseline.md) records the
inherited release commands, focused checks, full validation, environment-only
loopback retry, and clean adversarial verdict.

## Slice B — Universal Verified Exact-Body Operand

### B1 — Artifact Leaf

- replace checkpoint-only/dynamic policy exceptions with one identity-bound
  artifact leaf carrying body/source/cache identities, byte length/hash,
  topology signature, and resolved one-solid/one-or-more-solids policy;
- validate bytes only inside the geometry boundary; and
- keep leaves private and transferable.

### B2 — Artifact Downstream Sources

- add hole, linear pattern, circular pattern, mirror, and shell artifact-source
  variants using current tool/frame/reference contracts;
- parse the dependency B-rep once, execute, and derive result B-rep, metadata,
  topology, references, mass, display evidence, and signatures from one shape;
- inherit hole policy, allow pattern/mirror one-or-more, and require shell one;
  and
- never fall back to an older family recipe when an artifact is unavailable.

### B3 — Dependency Orchestration

- resolve policy before geometry;
- build or valid-cache-read one dependency artifact per body/generation;
- preserve ordered inputs, reject cycles and more than 4,096 nodes, and enforce
  existing per-artifact/aggregate limits; and
- verify identity before and after dependency/result construction.

### B4 — Ownership and Faults

- transfer without detached-buffer reuse;
- release dependency bytes, shapes, virtual files, and retained buffers on
  success, fault, cancellation, staleness, replacement, restart, and disposal;
  and
- cover corrupt/null/empty/non-finite/hash/length/topology/policy failures.

### Gate B

Gate B requires geometry-kernel, geometry-worker, OCCT/WASM, and app-runtime
focused tests plus real-OCCT same-shape and cleanup evidence for every new
operand variant.

B1-B4 and Gate B passed against implementation commit `38dd812`; the committed
[V21.1 Gate B closure evidence](./v21.1-b-baseline.md) records the artifact
contract, staged compatibility boundaries, serial focused/full checks, and
resolved adversarial findings.

## Slice C — Total Holes and Transactional Retarget

### C1 — Universal Hole Geometry

- accept every one-or-more-solid artifact target;
- apply the existing circular tool to every intersected solid, preserve
  non-intersected solids, and require at least one changed solid;
- implement the four retained depth/direction modes; and
- report atomic no-intersection, invalid-result, policy, identity, resource,
  stale, and cancellation failures.

### C2 — Retarget Transaction

- add target body/anchor validation to `feature.updateHole`;
- reject mixed fields, self, descendant, cycle, consumed, and unavailable
  targets;
- exact-preflight before commit; reactivate the old target, consume the new
  target, retain feature/result IDs, invalidate derived evidence, and emit the
  complete semantic diff in one transaction; and
- prove undo, redo, replay, save/open, and zero mutation on every failed path.

### C3 — Shared Product Path

- route human create/update and connected-agent commit through the same
  browser preflight and CADOps transaction;
- show all truthful targets in keyboard/pointer choosers with multi-solid
  warning, progress, Cancel, Retry, Escape, focus, narrow layout, live region,
  and technical diagnostics; and
- make the in-memory adapter dry-run only when exact preflight is unavailable.

### Gate C

Gate C requires the frozen hole matrix through real OCCT and STEP re-import,
protocol/core transaction tests, app chooser/accessibility tests, human/agent
preflight parity, and atomic fault/cleanup proof.

C1-C3 and Gate C passed against implementation commit `f144508`; the committed
[V21.1 Gate C closure evidence](./v21.1-c-baseline.md) records the universal
artifact cut, transactional retarget, shared human/agent product path, serial
regressions, real-OCCT AP242 round trip, and resolved adversarial findings.

## Slice D — Pattern, Mirror, and Shell Breadth

### D1 — Pattern and Mirror

- accept every one-or-more-solid artifact seed, including imported and
  recursive acyclic results;
- retain current direction/axis/plane, transforms, include-original,
  consumption, instance limits, and one-public-body behavior;
- preserve multi-solid warning and exact export semantics; and
- reject new create/update counts above 4,096 before allocating instance
  descriptors; historical projects remain readable but over-limit results are
  blocked from rebuild/downstream use.

### D2 — Shell

- accept every exact-ready one-solid artifact target;
- support closed shell and current generated/named/topology open-face refs;
- add the keyboard face list without widening viewport picking; and
- reject multi-solid and infeasible/invalid shell before commit.

### D3 — Consumer Parity and Deletion

- use the exhaustive policy plus current exact evidence in Solid, Project,
  Inspect, selection, reference readiness, display, topology, mass, STEP,
  human commands, and connected agents; and
- remove production extrude-family seed/target unions and recipe branches that
  compatibility readers no longer require.

### Gate D

Gate D requires every frozen pattern/mirror/shell row through real OCCT and
STEP re-import, recursive/cycle/limit/fault tests, cross-surface table tests,
accessibility checks, and a source-kind/dead-branch audit.

D1-D3 and Gate D passed against implementation commit `1de2fb0`; the committed

## Slice E — Exact Cache and Portability Recovery

### E1 — Derived OPFS Cache

- reuse existing OPFS/index/storage patterns;
- key by source identity, source cache hash, kernel protocol, OCCT fingerprint,
  writer version, and shape policy;
- on hit verify length/hash, parse a non-null shape, recompute metadata and
  topology, and match topology signature before readiness; and
- write only while identities remain current; otherwise cold-rebuild.

### E2 — Bounds, Eviction, and Clear

- enforce 128 MiB per entry and 512 MiB total;
- deterministic LRU eviction with bounded bookkeeping;
- remove corrupt/version-mismatched entries and cold-fallback on absent,
  denied, full, or unavailable OPFS; and
- add one Project/Storage clear-derived-exact-data action.

### E3 — Portability Projection

- keep JSON source-only and report portable JSON, `.wcad` required, or missing
  payload with every checkpoint ID;
- make `.wcad` primary for checkpoint-backed projects and label JSON clearly;
  and
- retain current schema and package versions.

### E4 — Atomic `.wcad` Recovery

- accept one user-selected package;
- match every requested manifest/checkpoint/body/feature/length/hash/topology/
  source identity before importing any payload;
- import no document source/history and never use the derived cache; and
- prove matching recovery -> save/open/export and mismatching all-or-nothing
  diagnostics.

The private cache namespace is `partbench-exact-artifact-v1`. LRU order is
`lastAccess`, then cache key as a deterministic tie-break. Clearing affects
only derived exact entries and invalidates an in-flight exact-cache generation
before removing entries. Public checkpoint ID and recovery diagnostic lists
are capped at 4,096 entries; public request IDs are capped at 128 characters.

### Gate E

Gate E requires valid/corrupt/version/stale cache paths, LRU/clear/cold
fallback and reconstruction-skip evidence, portability UI/accessibility, exact
recovery/mismatch/save-open-export proof, storage compatibility, and no eager
OPFS/OCCT startup.

## Slice F — Ready Subset and Agent Browser Export

### F1 — Explicit Ready Subset

- retain strict Export all;
- when ready and blocked active bodies coexist, list every canonical-order
  inclusion and exclusion/root blocker with AP242/unit/name/atomic wording;
- create an explicit ordered `bodyIds` plan without changing selection or
  future Export-all behavior; and
- fail atomically if any included body changes.

### F2 — Fifth Typed Agent Action

- add `cad.project_request_exact_export` with `all`, `readySubset`, or bounded
  explicit body IDs and optional expected source identity;
- add exactly one typed operation to the closed V20 browser port;
- reuse the browser planner/executor and return bounded metadata only; and
- reject path, filename, MIME, bytes, Blob, URL, handle, OPFS, or directory
  fields.

### F3 — Approval and Download Lifecycle

- reuse one pending commit-or-export proposal union;
- Manual shows one approve/reject proposal; Approve everything downloads valid
  plans immediately; invalid plans only return diagnostics;
- wait for approval, STEP completion, and the browser download request while
  returning `downloadRequested` rather than claiming unobservable completion;
  handle busy, reject, stale, cancel, restart, disconnect, New/Open,
  undo/redo/edit, writer, and pre-request failures; and
- restore focus and Manual mode under existing V20 rules.

Agent-owned export progress and Cancel live in the existing Agent proposal/job
surface. Focus returns to its request/approval control after every terminal
path. The exactly-256 release scenario uses 256 explicit ordered `bodyIds`, not
an inferred Export-all selection.

### Gate F

Gate F requires ready-subset UI/core/browser tests, strict Export-all
regression, both approval modes, one-proposal concurrency, security/private-
field audit, accessibility/focus proof, and V20 transport/security commands.

## Slice G — Full-Limit Release Proof

### G1 — Named Commands

Land all seven spec-named commands. Keep browser/cache/recovery/agent/download
proof in their named workflows rather than the default save loop.

### G2 — Production Browser Limit

- select exactly 256 lightweight active bodies;
- build/cache artifacts sequentially, write named AP242, download, re-import,
  and compare exact invariants;
- cancel and retry while proving next-frame progress, no representative
  main-thread task over 50 ms, bounded memory, and cleanup; and
- record cold/warm p50/p95 operation, artifact, STEP, recovery, eviction,
  restart, total, and byte-size measurements.

### G3 — Compatibility and Fixed Caps

- run all V19, V20, and V21 named commands serially;
- run repository test, typecheck, lint, format-check, and build;
- enforce unchanged UI/worker/WASM gzip caps;
- prove V1-V22 JSON, `.wcad` v2, history/redo, completed V12-V21 matrices, and
  minimum-schema behavior; and
- audit manifests for no new production dependency/package/version.

### G4 — Adversarial Simplification and Documentation

- inject every spec fault and source mutation boundary;
- audit for leaks, stale application, silent omissions, permission drift,
  private bytes/paths, recipe fallbacks, source-kind omissions, and partial
  non-goals;
- delete superseded narrow branches and unnecessary scaffolding; and
- reconcile architecture, implementation plan, native format, AGENTS, package
  docs, release record, this DAG, commands, metrics, and known non-goals.

### Gate G / Release

Gate G passes only when all 20 Must Definition of Done items have direct
evidence, all seven V21.1 commands and inherited release commands pass, the
exactly-256 production workflow passes, fixed caps hold, full validation is
green, docs agree, and no deferred Must or partially exposed non-goal remains.

## Review Checklist

Before accepting a gate, reviewers answer yes to every applicable question:

- Is the source/lifecycle decision from the exhaustive cad-core policy?
- Is the geometry operand a current verified identity-bound artifact leaf?
- Did human and agent execution use the same exact preflight and CADOps path?
- Did real OCCT produce and re-import every geometry row claimed ready?
- Are B-rep, metadata, topology, references, mass, display, and STEP derived
  from one result shape lifetime?
- Can source change here, and is the result rejected if it does?
- Are cancellation and every terminal fault atomic and leak-free?
- Are bytes, paths, handles, cache keys, and browser authority private?
- Do strict Export all and the two V20 approval modes remain unchanged?
- Are cache and recovery clearly derived versus authoritative?
- Do old schemas, packages, commands, matrices, and workflows remain green?
- Was superseded narrow code deleted, and is any non-goal partially exposed?

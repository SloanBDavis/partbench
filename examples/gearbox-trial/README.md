# Independent gearbox design trial

Baseline `adab4e078fd592e149b2d408996e978c4d0e86c5`, September 7, 2026.
The designer received the [mechanical brief](designer-brief.md) with no inherited
conversation or access to product source, development history or other examples.
The observer's findings and priorities are in [the trial report](../../docs/gearbox-trial.md).

The result is a connected CAD gearbox concept: eight finished definitions,
15 instances, initially 20/40 teeth at 45 mm centers and revised to 20/60 at
60 mm centers. Module 1.5, pressure angle 20°, face width 10 mm, gear bores
8.1 mm, shafts 8 mm. Teeth are chord approximations to involutes. The native
angle expression drives the output −180°/−120° for a 360° input turn.
Gear contact does not drive the solver. Torque/axial retention and manufacturing
validation remain incomplete.

## Reproduce the successful modeling path

From the repository root with Node 22 and pnpm 10:

```sh
pnpm --filter @web-cad/mcp-stdio-server build
node examples/gearbox-trial/replay.mjs
node examples/gearbox-trial/observer/verify-artifacts.mjs
pnpm smoke:ui-use -- examples/gearbox-trial/browser-use.json
```

`replay.mjs` uses the existing generic real-stdio MCP client. It creates a fresh
`.metrics/gearbox-trial/replay/`, executes the exact successful designer requests,
saves both revisions, exports nine STEP definitions, then checks source identity,
assemblies, eight volumes and a driven pose in a new process. It refuses an
existing output directory; an optional first argument selects another fresh
workspace. Give that directory to `observer/verify-artifacts.mjs` too, and adjust
the two `openWcad` fixture paths if running the browser against it.

`authoring-stages.json` contains nine ordered batches extracted from successful
raw calls; these requests are replay authority. The first seven make the 2:1
model including the corrected spacer clearance. The final two revise to 3:1 and
restore dimensions on the replacement support sketches. `geometry.mjs` and
`params.json` preserve the designer generator for inspection (formatting, an explicit Node URL import and an unused binding cleanup only); replay does not
regenerate or reinterpret its coordinates.

The observer independently counts teeth from saved source edges, compares gear
volumes with polygon integration minus the bore, exercises actual poses through
fresh MCP sessions, and reads exported gear STEP solids back through OCCT. It
also checks authored polygon overlap at 73 ideal poses per ratio. This sampled
2D check does not prove continuous 3D collision freedom. Generated observer
reports go to `.metrics/gearbox-trial/observer/`; checked-in evidence remains the
historical baseline observation.

The browser fixture uses the existing Bun/Chrome runner: real native Open,
parameter editing, Undo/Redo, and an empty-field rejection in a fresh tab. Each
structure assertion waits for all active exact/display results. This is an
explicit diagnostic, **not part of the fast default E2E suite**. It can take
minutes because angle edits trigger expensive gear rebuilding.

A small independent source-composition reproduction is available separately:

```sh
node examples/gearbox-trial/observer/cut-repro.mjs
```

It compares the same square authored as four lines versus a rectangle, then
cuts a circular bore. At baseline, wire target rejection is atomic while the
rectangle target succeeds. The script intentionally records this current
restriction; revisit its expected outcome when fixing that behavior.

- [Designer journal](designer-journal.md) and [outcome](designer-outcome.md) are
  unchanged historical records. Their original relative paths refer to the raw

  [small composition reproduction](evidence/cut-repro.json),

  [after motion/Redo](evidence/gearbox-trial-browser-motion.png),
  [blocked empty angle](evidence/gearbox-trial-empty-angle.png).
- Original native/STEP files, schemas, logs and all authoring helpers are in
  `.metrics/gearbox-trial/designer/`. Its `gearbox-design-trial.tar.gz` is the
  complete original bundle. [SHA-256 manifest](evidence/raw-manifest.json) records
  that raw directory. Large outputs are regenerated by replay, not checked in.

STEP exports contain individual definitions in local coordinates. Native WCAD
preserves the assembly and mate expressions. The independent STEP readback
covers the three unique gears; other exported parts have designer exact-volume
checks and successful replay/export/reopen evidence.
